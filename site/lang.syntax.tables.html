lang.syntax.tables

The tables that say how kinds nest and are told apart, part of the grammar with grammar.vun and nodes.vun, whose productions name them (the header of grammar.vun says how all are read).

value parts

parts := [ .\mut, .qualifier, .mode, .raw_string_line, .select, .namespace, .returns, .guard, .label, .binding, .typed_binding, .field, .assign, .spread, .implementation, .extension, .delegation, .field_init, .param, .test, .in, .arm, .module_doc, .staged, ]

Kinds that are never operands: they stand only in the fields that name them, hold them or admit them.

value admits

admits := [ .{ .fields = &[.statements], .kinds = &[.binding, .typed_binding, .field, .assign, .spread, .module_doc, .staged], }, .{ .fields = &[.items, .values, .args, .fields, .variants], .kinds = &[.field_init, .staged] }, .{ .fields = &[.params], .kinds = &[.param] }, .{ .fields = &[.head, .condition], .kinds = &[.test, .\in] }, // A pattern may bind the whole value it matches: `n := .some(x) => n`. .{ .fields = &[.pattern], .kinds = &[.binding] }, // What `defer` runs may be an assignment, looser than any operator: `defer x.* = 0`. .{ .fields = &[.body], .kinds = &[.assign] }, ]

Fields holding the kinds listed besides any operand: the entries of lists, the forms of heads and patterns.

value holds

holds := [ .{ .fields = &[.members], .kinds = &[ .binding, .typed_binding, .field, .spread, .implementation, .extension, .delegation, .module_doc, .staged, ], }, .{ .fields = &[.arms], .kinds = &[.arm, .staged] }, .{ .fields = &[.otherwise], .kinds = &[.block, .\if] }, .{ .fields = &[.names], .kinds = &[.name] }, ]

Fields holding only the kinds listed: files and struct bodies hold declarations.

value preferred

preferred := [ &[.paren, .tuple, .fn_type], &[.tuple, .fn_type], &[.\fn, .tuple, .fn_type], &[.typed_binding, .field], &[.array, .closure], &[.closure, .array_type], &[.assign, .field_init], &[.spread, .prefix], &[.staged, .prefix], &[.block, .typed_lit], ]

Kinds that may spell the same source, which the parser tells apart by what follows them or what they hold, each listed before those it is preferred to where several fit: () is a tuple, () {} a function. Editor grammars that try each keep the preferred.

value transparent

transparent := [ .{ .kind = .prefix, .tokens = &[.dollar, .\unsafe] }, .{ .kind = .doc, .tokens = &[.doc_comment] }, .{ .kind = .attr, .tokens = &[.hash_l_bracket] }, ]

Kinds that end with the kind of their last child when written with one of the tokens listed: unsafe {} is unterminated as a block is, .$(e) names a member as .(e) would, and #[a] x: T, is a field as x: T, is.

value precedence

precedence := [ &[ .doc, .attr, .binding, .typed_binding, .field, .implementation, .extension, .delegation, .assign, .field_init, .param, .test, .in, .arm, .\defer, ], &[.\if, .\for, .\match], &[.\return, .\break, .\yield, .labeled, .returns, .guard], &[.infix], &[.prefix, .spread, .array_type], &[.member, .call, .index, .postfix, .dot_name, .closure, .qualifier, .mode], ]

How tightly the forms whose productions begin or end with an operand hold it, loosest first, as the parser nests them (spec 01, section 6); infix stands for the levels of the table infix. Editor grammars resolve by it what the parser decides by nesting.
