std.os

Hosted runtimes and the System capability (spec 08, section 2). A hosted program is start := std.os.start(main); the runtime makes the one System and passes it to main.

Namespaces

  • std.os.file

    Files a hosted program opens through its std.os.System (spec 08, section 2).

  • std.os.libc

    A runtime on top of the C library: exports C main, the trap handler, the critical section and the executors' sleep, and reaches the system through the C library's functions (spec 08, section 2).

  • std.os.library

    Libraries a hosted program loads as it runs (spec 08, section 2): shared objects the system finds by path or name, whose functions the program calls once it has their addresses. The system names a library by a number, as it does a file.

  • std.os.linux

    Linux.

  • std.os.macos

    macOS.

  • std.os.memory

    The functions of C's string.h a freestanding C program must provide, which a C compiler calls for copies and fills of its own: a runtime with no C library holds them. Copies and fills are written in assembly: a loop in Vun would be read back by the C compiler as a call of the function it is.

  • std.os.pages

    The pages of the process's own address space (spec 08, section 2): what a range of them allows, and the range an address is mapped within. An address passed here must be one the system gave the process: through a library it loaded, its own code and data, or memory it mapped.

  • std.os.thread

    Threads the system runs beside the one starting them (spec 08, section 2). A thread runs a closure borrowed for as long as it runs: Thread is linear and holds the borrow, so the closure, and what it borrows, stay until the thread is joined, and joining gives what the closure returned. Values safe to share are safe to share across threads (spec 07, section 2), so a closure may borrow what the thread starting it goes on reading.

  • std.os.wasi

    WASI preview 1 (spec 08, section 2): a runtime exporting _start, which reaches the system through the functions of preview 1's import module. A module runs one thread and takes no signals, so its critical section is nothing to take.

  • std.os.windows

    Windows (spec 08, section 2): a runtime calling kernel32 itself, with no C runtime, for programs that run one thread. A file number is a handle (file), the command line is split into arguments by the C runtime's rules (command_line), and the system's errors are the ones std.os.Error names, or its own number.

type Status

Status: type = Int(1..=125)

A status a process ends with, besides success: what every system passes on unchanged. A shell reads 126 and 127 as a program that could not run and 128 plus n as one killed by signal n, and WASI's proc_exit refuses 126 and above.
