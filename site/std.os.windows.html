std.os.windows

Windows (spec 08, section 2): a runtime calling kernel32 itself, with no C runtime, for programs that run one thread. A file number is a handle (file), the command line is split into arguments by the C runtime's rules (command_line), and the system's errors are the ones std.os.Error names, or its own number.

Namespaces

  • std.os.windows.clock

    The system's clocks and sleep, in the units std.time keeps.

  • std.os.windows.command_line

    The command line of a Windows process: one string of UTF-16, which a program splits into its arguments itself. The rules are the C runtime's, as Microsoft documents them:

  • std.os.windows.file

    Files as the system hands them out: handles, which a std.os file number stands for, the modes std.os.file.Mode asks for in the system's words, and paths in UTF-16.

  • std.os.windows.kernel32

    The functions of kernel32 the runtime calls, each by its link symbol (spec 08, section 3): the system's own, which a program of this runtime links by name and no C runtime stands between. They are stdcall, the system's convention on 32-bit x86, which x86-64 takes for its one. A handle is a usize, a BOOL an i32, a DWORD a u32.

  • std.os.windows.library

    Loading libraries through kernel32: the exports a runtime holds, library := std.os.windows.library.exports. A module's number is its handle, the address it is loaded at; the loader reports a failure as an error number, which none here is told apart by, so each is unresolved.

  • std.os.windows.pages

    Pages as VirtualProtect and VirtualQuery take and give them: PAGE_*'s eight kinds of access, and the fields of MEMORY_BASIC_INFORMATION past AllocationBase, which a pointer's width places: AllocationProtect is padded to keep RegionSize a pointer's width aligned, so the longest a pointer is wide places every field from it on.

  • std.os.windows.stack

    The stack probe a Windows program provides. Windows commits a thread's stack a page at a time, as the thread touches the guard page below what it has committed, so a function with a frame of more than a page touches each page of it in order first: it calls __chkstk with the size of its frame in rax, and the call leaves every register but r10, r11 and the flags as they were. The frame itself is taken by the caller after it.

  • std.os.windows.tests

    Tests of std.os.windows: a command line split into the arguments a program is given, and a clock before the epoch.

value command_line_max

command_line_max := 32767

The most UTF-16 units the system gives a command line (CreateProcess), which are the most a program is started with. It has an argument for every two of them at most, an argument and its separator, and each unit is at most three bytes of UTF-8, with a zero after each argument. So entry holds every argument a program is started with in its frame, which lasts as long as the program, and a command line never does not fit.
