lang

Primitives of Vun.

Every declaration whose value is _ is provided by the compiler. Syntax desugars only into items of this package (spec appendix B), so reading it tells you what the syntax means.

Namespaces

  • lang.abi

    Calling conventions (spec 07, section 4).

  • lang.arch

    The instruction sets a block of instructions is written in, each a namespace declaring its table (spec 07, section 6): x86_64, arm64, thumb and wasm32; and what a block is written with, whatever its instruction set.

  • lang.bounds

    What bounds hold (spec 04): the iterator of lang.Bounds in lang.ops reads them.

  • lang.check

    Checks of unsafe code at run time (spec 07, section 7; spec 13, section 8.7): what a program may be built to check, the operations its runtime provides for the checks, and how a failed one is reported.

  • lang.comptime

    Compile-time evaluation budgets (spec 03, section 7).

  • lang.cover

    Coverage (spec 11, section 6): a program built covered, as vun fuzz builds one, sets the flag of each block of its code in map as the block starts, the flag of the block's number modulo size. std.testing.fuzz reads the flags to tell inputs apart by what they ran.

  • lang.diag

    Diagnostics as values (spec 10).

  • lang.errors

    Every compiler diagnostic, grouped by area. cargo gen derives the ids of vun-diag from this file. Each entry's explanation page is the file its binding path names, errors/<group>/<name>.md (spec 10, section 1).

  • lang.float

    Floating-point operations that are explicit about precision (spec 04, section 2).

  • lang.flow

    Guaranteed tail calls (spec 09, section 3).

  • lang.hint

    Hints inside function bodies (spec 09, section 3).

  • lang.int

    Integer types by width (spec 04, section 1). lang declares them, since its own declarations need them; std.prelude re-exports them.

  • lang.kind

    Kind restrictions (spec 05, section 1).

  • lang.layout

    Layout attributes (spec 05, section 6).

  • lang.link

    Linking attributes (spec 08).

  • lang.lint

    Lints as values (spec 10, section 4). A lint states its group, its default level and a check for each kind of node it looks at; the compiler walks the typed code once per file and runs each check a lint states on each node of its kind, at compile time. A check sees the code through Cx and the nodes as plain data, a view versioned with lang, and reports by appending to Cx: running it is a pure compile-time call.

  • lang.lower

    How the compiler lowers what no instruction computes (spec 13, section 3).

  • lang.mem

    Borrows, raw pointers and memory access (spec 05).

  • lang.meta

    Code values, names, reflection and origins (spec 03).

  • lang.ops

    Operators as interfaces. Every operator desugars to one of these (spec 02, section 4); the table operators of lang.syntax.desugar says which.

  • lang.opt

    Optimization controls; none changes meaning (spec 09, section 3).

  • lang.panic

    Traps and the typed link symbol that handles them (spec 07, section 3; spec 08).

  • lang.safety

    What unsafe marks (spec 07, section 4): something used only where someone vouched for the facts the compiler cannot check. A block or expression is vouched for where it is written; a function, or a function type, at each call.

  • lang.scope

    Where a restricted name is visible (spec 01, section 7): the argument of lang.visible.

  • lang.simd

    Vector types (spec 04, section 3): lanes values of one type, operated on together. A vector is laid out as the array of its lanes, aligned to its size when that is a power of two; lanes and of move between the two, over which std.simd gives vectors their operators and methods.

  • lang.stack

    Stack bounds (spec 07, section 4).

  • lang.syntax

    The syntax of Vun as types, for compile-time code reading code values (spec 03, section 4). Token and node types are generated from syntax/grammar.vun.

  • lang.target

    Target descriptions and feature requirements.

  • lang.thread

    Storage per thread (spec 07, section 2).

  • lang.trace

    What the compiler tells a program of its own code, so that a trap reports where it was written and the calls that led to it (spec 07, section 3): the program's functions, its trap sites and the places in source they name. The compiler lays the table out as these declarations do and gives it the link symbol symbols.table, which a runtime declares to read it.

function Bounds

Bounds: ($T: type) -> type = _

The type of a..b, a..=b and a.. at run time: bounds whose items are all values of T, so 0..n with n: u8 is Bounds(Int(0..=254)). Where a Range is expected, bounds are that range.

function Fn

Fn: ($params: type, $result: type) -> type = _

The type of functions from a tuple of params to result: (A, B) -> R is Fn((A, B), R) (appendix B).

function Pack

Pack: ($items: type) -> type = _

The type of a function's last parameter when it gathers the arguments after the others into a tuple of the types items: (A, ..P) -> R is Fn((A, Pack(P)), R) (spec 01, section 4).

function Float

Float: ($bits: Int(1..)) -> type = _

The IEEE 754 binary floats of bits bits: 16, 32 or 64 (spec 04, section 2).

struct Attribute

Attribute := ($on: &[Place]) -> type { struct { ... } }

The type of an attribute written only at the places on; the compiler reports one written elsewhere. An attribute of any other type is plain data, written anywhere.

function impl

impl: ($witness: type) -> Attribute(&[Place.decls]) = _

#[impl(I(T))]: checks and registers a witness of the interface I for T (spec 02, section 3).

function derive

derive: ($witness: ($T: type) -> type) -> Attribute(&[Place.decls]) = _

#[derive(f)] on an interface: a struct or an enum with no impl of it has the witness f(T), built by reflection, when every part of it has the interface too (spec 02, section 3).

function visible

visible: ($scope: scope.Scope) -> Attribute(&[Place.decls, Place.fields]) = _

#[visible(scope)]: widens where a name starting with _ is visible from its namespace to scope (spec 01, section 7).
