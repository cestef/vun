std.check

Shadow memory for the checks of unsafe code at run time (spec 07, section 7; spec 13, section 8.7): one byte for each granule bytes of the address space, 0 where all of them may be accessed, k where the first k may, and a negative code saying why where none may. The shadow of each span of 1 << span_bits addresses is reserved the first time memory in it is described, so it follows the program's memory wherever the system puts it. A runtime gives how memory is mapped (mapped) and exports the operations of lang.check over the state (exports). The state is read and written by atomic accesses, which no check rewrites.

Namespaces

  • std.check.quarantine

    Memory given back to allocators, held poisoned before they may hand it out again (spec 13, section 8.7): a ring of what was given back, oldest first. Past lang.check.quarantine bytes, each free gives back the oldest memory of the allocator freeing, so memory leaves only for an allocator known to be alive.

  • std.check.stack

    The checks of the stack (spec 13, section 8.7): the export of a runtime that checks the frames of its stack and nothing else, over the bounds it knows.

  • std.check.table

    What allocators have handed out, for the checks of allocations (spec 13, section 8.7): the bytes handed out at each address, open-addressed by linear probing. A removal moves later entries of its run back rather than leaving a tombstone, so probes stay as short as the table is full.

  • std.check.words

    Words of memory a runtime gives the checks, read and written by atomic accesses, which no check rewrites.
