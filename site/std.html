Documentation

    std

    The standard library: ordinary code over lang, holding no privilege user code lacks.

    Namespaces

    • std.build

      The build API used by build.vun files (spec 12, section 2). build runs at compile time, in the sandbox, with a &mut Build capability, and records a plan: steps that the driver carries out once it returns. What only the package knows, its dependencies' names and parameters, a program's options, is written as records, which the driver reads by reflection (decision 116).

    • std.check

      Shadow memory for the checks of unsafe code at run time (spec 07, section 7; spec 13, section 8.7): one byte for each granule bytes of the address space, 0 where all of them may be accessed, k where the first k may, and a negative code saying why where none may. The shadow of each span of 1 << span_bits addresses is reserved the first time memory in it is described, so it follows the program's memory wherever the system puts it. A runtime gives how memory is mapped (mapped) and exports the operations of lang.check over the state (exports). The state is read and written by atomic accesses, which no check rewrites.

    • std.cmp

      Comparing values through lang.ops.PartialOrd, whose < and > these use.

    • std.codec

      Codecs: bytes as text in the encodings of RFC 4648 (Base: hex, base32, base64) and as variable-length integers (varint). Encoders write to any std.fmt.Writer and decoders write the bytes to one, so none of them needs an allocator. Checksums are std.hash.crc32 and std.hash.adler32.

    • std.collections

      Collections: Vec, a growable array over an allocator the caller passes, struct-of-arrays layouts generated by reflection, and Handle(T), typed indices into a pool over nominal structs (decision 41, spec 05, section 4).

    • std.diag

      Diagnostics from compile-time code (spec 10, section 3).

    • std.float

      Float methods (spec 04, section 2): conversions, an impl for every float type over the primitives of lang.float.

    • std.fmt

      Formatting, with format strings read at compile time (spec 03, section 4): print(w, "{} args\n", n) writes the text of the format string with each {} replaced by the next argument, as its Format impl writes it. Another specifier between the braces writes it another way: {?} by Debug, {x} by Hex and {b} by Binary. After a : goes where it sits in a width: {:>8} pads on the left to 8 bytes, {x:0>4} with 0, {:^5} on both sides.

    • std.hash

      Hashing: a value feeds its parts to a Hasher, which answers a u64. Values that are equal (lang.ops.Eq) hash equal. A struct or an enum whose parts can be hashed can be hashed without an impl, by derive_hash; Fnv is a hasher for tables.

    • std.hw

      Hardware access: memory-mapped registers over volatile operations.

    • std.int

      Integer methods (spec 04, section 3): narrowing to another integer type, an impl for every Int(r) over the primitives of lang.int.

    • std.io

      Moving bytes: Reader, where bytes come from, and Writer (std.fmt.Writer), where they go; a reader over a borrowed slice. Streams of the system are readers and writers (std.os.Stream), and so are the buffers of std.text.

    • std.iter

      Iteration is suspension (spec 06, section 3): an iterator is a coroutine yielding its items, and adapters are coroutine functions over one, methods of every frame.

    • std.lints

      The standard lints, grouped (spec 10, section 4): each group is a namespace, which configuring names, as std.lints.pedantic, and which declares its default level.

    • std.log

      Deferred logging: format strings interned in a non-loaded section (spec 12, section 9).

    • std.mem

      Memory: allocators, owning pointers, copying, and Arena, which hands out &mut T tied to the arena borrow so that trees are ordinary scoped values (decision 40, spec 05, section 4).

    • std.meta

      Reflection and code generation helpers over lang.meta (spec 03), including collect(package, attr), which gathers declarations carrying an attribute (decision 42).

    • std.option

      Options: methods of every ?T, by an impl without an interface.

    • std.os

      Hosted runtimes and the System capability (spec 08, section 2). A hosted program is start := std.os.start(main); the runtime makes the one System and passes it to main.

    • std.panic

      Ending the execution context (spec 07, section 3): fail is a trap site with a message.

    • std.prelude

      Names every file sees without qualification, unless its manifest lists another prelude (.prelude, spec 01, section 8).

    • std.ptr

      Raw pointers (spec 05, section 5): methods of every *T over the primitives of lang.mem. Creating a pointer and reading its address are safe; the rest is unsafe to call, and each body vouches for the primitive it calls.

    • std.rand

      Random numbers: an Rng answers a u64 each time it is asked and holds its state, so a seed fixes everything it gives. These generators are not for secrets. The default methods draw bounded numbers, bytes and shuffles from next, whichever generator gives it.

    • std.re

      Tools for reading binaries, which a program of its own builds on: byte patterns with wildcards (Pattern), as a reverse engineer writes them, and a hex dump of bytes (hexdump).

    • std.result

      Results (spec 07, section 3): methods of every Result(T, E), by an impl without an interface.

    • std.seq

      Arrays and slices (spec 05): what every [n]T and [T] answers, by impls for lang.mem.Array and lang.mem.Slice over the primitives of lang.mem.

    • std.simd

      Portable vector code (spec 04, section 3): the methods and operators of every lang.simd.Vector(n, T), lane by lane over the array of its lanes. An operator's lanes have the type the same operator gives their lanes (u8 lanes sum to Int(0..=510) lanes).

    • std.sync

      Synchronized interior mutability; the only safe kind (spec 07, section 2). A critical section is global mutual exclusion: Shared(T) is reached only with the &Critical it lends, and Atomic(T) and Mutex(T) synchronize by themselves.

    • std.task

      Asynchronous tasks and executors (spec 06). A task yields Wait requests; the executor, not the task, owns wakeups. Executors are library code over frames: run for bare metal, block_on for one task on a hosted system, select inside a task.

    • std.testing

      Tests, properties, benchmarks and simulation (spec 11). The runner is an ordinary program: start := std.testing.runner(app); runs every test of the namespace app and those nested in it, each on a thread of its own, since a trap ends only its thread (spec 07, section 3), and writes one JSON line per test, then one of the totals (spec 11, section 3). A test whose one parameter is &mut Bench is a benchmark (std.testing.bench), one whose one parameter is &mut Sim a simulation (std.testing.sim); a test with other parameters is a property, run with arguments generated from their types (std.testing.property), as a simulation runs with its schedules drawn from the same choices.

    • std.text

      Text (decision 43): bytes held, written and cut. Slab(n) keeps up to n bytes inline, with no allocator; text is UTF-8 in &[u8], whose bytes ascii classifies and whose code points utf8 reads. Formatting is std.fmt, readers and writers are std.io, maps are std.collections.

    • std.time

      Time as the system keeps it (spec 08, section 2): spans of time, and readings of the clocks a hosted program reaches through its std.os.System.

    • std.trace

      Backtraces (spec 07, section 3): where a trap was written and the calls that led to it, read from the program's table (lang.trace) and the chain of frames every function keeps, a record of its caller's frame and of where it returns to at its frame pointer. A runtime's handler of traps writes one before ending the program.
