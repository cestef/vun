std.testing

Tests, properties, benchmarks and simulation (spec 11). The runner is an ordinary program: start := std.testing.runner(app); runs every test of the namespace app and those nested in it, each on a thread of its own, since a trap ends only its thread (spec 07, section 3), and writes one JSON line per test, then one of the totals (spec 11, section 3). A test whose one parameter is &mut Bench is a benchmark (std.testing.bench), one whose one parameter is &mut Sim a simulation (std.testing.sim); a test with other parameters is a property, run with arguments generated from their types (std.testing.property), as a simulation runs with its schedules drawn from the same choices.

Namespaces

  • std.testing.bench

    Benchmarks (spec 11, section 5): a test whose one parameter is &mut std.testing.Bench. Run as a test, its loop runs the body once; measured (vun bench), the loop runs the body in batches, each as many times as all before it, until it has run least nanoseconds, and the benchmark reports how many times the body ran and how long that took. The clock is read between batches only, and the body never sees how many times it runs.

  • std.testing.fuzz

    Coverage-guided fuzzing (spec 11, section 2): vun fuzz builds the tests covered (spec 11, section 6) and runs each property, fuzz target and simulation over as many cases as --fuzz asks. A case replays the choices of a stream kept, mutated, then draws; or draws new ones. It is kept in turn when it set a flag of lang.cover.map no case before set, so the streams kept reach ever more of the code. A case that traps is shrunk and reported as a property's is.

  • std.testing.options

    How a run of the tests' program is asked for: the options its arguments give (spec 11, section 3).

  • std.testing.property

    Property tests (spec 11, section 2): a test's arguments are generated from its parameters' types, each read from a stream of choices, so the case that fails is replayed and shrunk as its choices, whatever generated it. A parameter whose type borrows, such as &[u8], is lent what the case holds for it (lend).

  • std.testing.sim

    Deterministic simulation (spec 11, section 4): a test whose one parameter is &mut Sim runs tasks, std.task.Async frames, on a virtual clock, one at a time, each next one chosen among those ready by the case's choices. They are the choices a property's arguments are read from, so a simulation runs over the cases a property does, a failing one is shrunk on its choices, and --seed replays it exactly. Time passes only when no task is ready: the clock jumps to the earliest time a task sleeps until.
