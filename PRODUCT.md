# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Astro 7 in `site/` with Starlight for the guide and Solid 2 islands for the editor, the course's checks and the playground; TypeScript 7; CSS written by hand on one set of tokens (`site/src/styles/tokens.css`). Deployed to GitHub Pages by `.github/workflows/site.yml`. Pages are static; the playground and the course run the compiler built for WASI in the browser.

## Users

Programmers evaluating or starting with Vun: mostly systems, embedded and Rust-adjacent developers, plus curious newcomers (confirmed: broader than the experts). They arrive at the landing page, then read the guide (`/docs/`), take the course inside it (`/docs/learn/`) or open the playground (`/play/`).

## Product Purpose

Vun is a small systems programming language for code that runs under constraints: firmware, kernels, runtimes, servers. The site shows what it is, gets a person to install it, teaches it, and documents how to use the toolchain. Success is a first program running (`vun new`, `vun run`) and a reader who knows where the rest of the answers are.

## Positioning

Everything is a binding, nothing is ambient (`sys` is handed to `main`), and the language, library and toolchain are declared in Vun itself with no privileged names. The compiler is also the teacher: diagnostics have ids (`vun explain`) and fixes (`vun fix`).

## Operating Context

Install is download, read, run (`install.sh` is served as a file and never piped into a shell). The toolchain is one binary, `vun`, with everyday verbs at the root (`new`, `run`, `build`, `check`, `test`, `fmt`, `fix`, `explain`, `doc`) and nouns as groups (`pkg`, `target`, `toolchain`, `component`, `util`, `debug`). Targets are paths such as `linux.x86_64.gnu`, `wasi.wasm32.p1`, `bare.thumbv7em.eabihf`. Version at time of writing: 0.2.0, experimental.

## Capabilities and Constraints

- Static hosting; the playground needs cross-origin isolation headers (`site/public/_headers`).
- Public copy is dry and factual: no slogans, no startup phrasing, no em dashes.
- The playground editor and the course are product surfaces of their own and keep their behavior.
- API reference pages are generated by `vun doc --library` and served at `/api/` (git-ignored).

## Brand Commitments

Name `vun`, the v/un mark and mascot, `assets/palette.toml` and the code colors as tokens with light, dark and system themes, JetBrains Mono, tagline "a smol systems programming language :3". Licensed DBAD or QUACK. Confirmed for this redesign: keep the brand, redo layout and structure.

## Evidence on Hand

Real code card images in `assets/cards/`, benchmark cards (`assets/cards/bench`), the lessons in `site/src/content/docs/docs/learn/`, the corpus programs, and the CLI help. No testimonials, customers or users to cite; none may be invented.

## Product Principles

1. Show real things: real programs, real commands, real compiler output.
2. One shell and one set of tokens across the landing page, the guide with its course, and the playground.
3. Say what is true and verified; mark the experimental status plainly.
4. The docs are checked against the compiler, as the lessons are.

## Accessibility & Inclusion

Keyboard operable throughout, visible focus, contrast in both schemes, reduced motion respected (`site/src/styles/landing.css` and the motion code check it).
