# 363. Property tests' gaps

Status: accepted
Where: 03, 11

Property tests' gaps: reflection's one shape covers tuples (one variant, its items as parts named by
position) and records (one variant, its fields), so `variants`, `part`, `make`, derives and
generation handle them, and `lang.meta.items(T)` is none for a non-tuple; `std.fmt.json` writes a
tuple as an array and a float as a number of its shortest digits (`null` for a NaN and an infinity,
decision 490); `Arbitrary` for floats (the encoding one choice, bounded by its width) and arrays
(item by item); a borrowing parameter is lent what its case holds (`std.testing.property.lend.Lent`,
on `lang.mem.Ref`), what a borrow reaches with no value of its own stored its way (`Store`, a slice
as a `Prefix` of up to 32 items), so fuzz targets (`&[u8]`) run as properties; `#[test.gen(g)]` on a
parameter generates it with `g`; an attribute is typed before it is evaluated, so one inferring `$`
arguments has a value; `vun test --seed n --cases n`, passed as the runner's arguments and read by
`std.testing.Options` (`vun_driver::testing::Options`); `vun_command::Values::Count` checks a whole
number; `Int(r).parse(text)` reads decimal digits; the test runner's case is a closure again
(decision 362)
