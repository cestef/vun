# 359. Typing gives every form of a body a type or says why

Status: accepted
Where: 02, 13
Note: the owner approved the type of generic functions

Typing gives every form of a body a type or says why: a form it gives none, reporting nothing, is
recorded where the gap starts with a typed reason (`GaveUp`: the rule of the form's kind, the
`Unevaluated` type of what a name reaches, or a type whose members are not all known here); lowering
reports a body it stops in at that form, with the reason, `vun debug dump types` marks each and
`VUN_LOG=vun_sema=debug` logs each, and a test requires none in any body a corpus program reaches.
Rules filling the gaps it found: a function with `$` parameters named as a value is of its own type
(`TyKind::Generic`), whose only value it is, existing at compile time only, and accepted where a
function type is expected, the call instantiating it deciding (an impl's `lt := lang.int.less`); a
name whose declaration's type is not known apart from its value (a requirement an impl provides) has
its value's type; any expression whose value is a type names that type's members, not only a path
(`Thread(R, F).spawn`); `*T` and `?T` written as expressions are types, as `[n]T` is; `defer e` is
`()`; `_` has the type its context gives it, and `_ = e` the value's; a `lang.Range` value is of
type `lang.Range`
