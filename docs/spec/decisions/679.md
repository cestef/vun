# 679. A variant of an enum names its tag, `name = code`

Status: accepted
Where: 05

A variant of an enum names its tag, `name = code` (a form `.variants` already parsed, which HIR
dropped without a word): the tag of a variant that does not is one more than the one before, 0 for
the first. Such an enum holds nothing in its variants, has no niche, and is stored as the integer of
`#[layout.tag(T)]` (any integer type holding every tag) or the least one holding them, a negative
tag in two's complement: `layout::Tag::Index` carries the patterns (`Tag::pattern`),
`MemberTable::codes` the tags, and lowering writes, compares and constants use them; `variant_index`
tells coded tags apart one by one. `layout.code` reports a variant holding a value, two sharing a
tag, a tag outside its type. `lang.meta.Variant.code` is a variant's tag or position;
`std.meta.variant_code` and `std.meta.from_code` convert, so the binder can bind a C enum whose
values it knows
