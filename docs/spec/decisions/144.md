# 144. Every operator is its interface's function for the left operand's type

Status: accepted
Where: 02, 04, 13
Note: the user chose all operators through impls and derived `Eq`

Every operator is its interface's function for the left operand's type, integers and floats
included: `lang.int.ops` and `lang.float.ops` hold impls whose functions are primitives (`add :=
lang.int.add`), whose signatures state spec 04's rules through range primitives (`sum`, `quotient`,
`bitwise`, `shifted_left`, ...; an empty range is the empty type); arithmetic, bit and concatenation
interfaces take the right operand's type per call (`Output($R)`); `Neg`, `Not` and the table
`prefix_operators`; operands are passed as the parameters ask, through borrows; compound assignments
and literal and range patterns are operator calls (`TypedBody.operators`, MIR calls;
`Rvalue::Binary` and `Unary` gone, `Not` for `!`); calls of primitives infer omitted `$` arguments
as function calls do (`Callable`); `panic.never` asks a primitive whether its compile-time arguments
let it trap (a divisor range without 0 does not); `Eq` for `Option`, `Result`, slices, arrays and
types, `std.cmp.derive_eq` by `lang.meta.variants`/`variant`/`fields`, `++` on sequences through
`lang.meta.concat`; a chained comparison is an error node; `$(e) :=` is `PatKind::Computed`
