# 366. One name per concept, and a command showing each

Status: accepted
Where: 12, 13
Note: the user chose the model, the names and `ffi`

One name per concept, and a command showing each: a toolchain is a release (`bin/vun` and `lib/`,
decision 364), a component a backend or linker compiled in, a target a `Spec`, tools the machine's
programs for a target. The machine's file is the tools file, `vun/tools.vun` (declaration `tools`,
`VUN_TOOLS`; `vun_build::tools::{Tools, TargetTools}`), freeing `VUN_TOOLCHAIN` for pinning.
Components declare the programs they run (`vun_target::Run`: the target's `Compiler` or `Archiver`,
or a `Program` by name; `BackendInfo.runs`, `LinkerInfo.runs`, `Linker::runs` where the format
decides, as lld's does); a backend declares the object formats it writes (`BackendInfo.formats`,
`Names`, generalizing `Arches`) and choosing one checks them (`Unfit::Unsupported`); choosing says
how (`Picked`, `Pick::{Named, Preferred}` with the preferences passed over; `Linkage`,
`Link::{Named, Target, Instead}`, a fallback logged). `lang.target.CCompiler.builds_for`
(`BuildsFor::{target, host}`) says whether its command builds for the target or for the machine
running it, as Linux's `cc`. `vun_driver::setup::Setup` resolves a build's parts for a target as a
build does: backend, linker, each program found, missing or building for the host (`Found`), the
sysroot, and where programs run (`Runs::{Here, Through, Elsewhere}`), each with where it is declared
(`From::{Target, Tools, Component}`). `vun target list` and `vun target show [file]` show it
(`vun_sema::target::Targets` lists every target with its `TargetPath`); `vun toolchain show`
replaces `components`, adding the version and where the library is and why. `vun tool` is `vun ffi`
