# 670. The distributed `vun` is optimized by a profile of its own workloads

Status: accepted

The distributed `vun` is optimized by a profile of its own workloads (PGO). `cargo xtask pgo` builds
a `vun` that records what runs (`-Cprofile-generate`, the `release` profile, with the components
linked in so it runs without their libraries), runs it over `vun debug profile check-hello
check-tour check-comptime check-std build-hello build-tour run-fib`, and merges the records with
rustup's `llvm-profdata` into `target/pgo/vun.profdata`; a `dist` build uses it (`-Cprofile-use`),
in the release workflow on each machine for its own architecture and in `cargo xtask install`, which
builds without it where `llvm-tools` is missing. On am3 (arm64), `release` against `release`:
`build-hello` 355 to 314 ms cold and 33.9 to 29.6 ms warm, `check-std` 3.77 to 3.28 s cold and 613
to 523 ms warm. On petal, `dist` (fat LTO) against `dist`: `build-hello` 490 to 450 ms cold and 34.3
to 27.7 ms warm, `check-std` 9.57 to 9.48 s cold and 895 to 861 ms warm, within the spread: over fat
LTO the gain is in building, not in checking. BOLT over both measured within noise (am3, `llvm-bolt`
22) and is not used. mimalloc moved to v3 (0.1.52), which measured the same as v2.
