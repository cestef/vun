# 310. Native code is compiled for a processor

Status: accepted
Where: 07, 13

Native code is compiled for a processor: `vun_isa::Processor<F>` (the target's `features` as the
instruction set's generated `Feature` enum, which every generated table enum implements
`vun_isa::Enumerated` for, and its `floats`) is built once from the target and held by the code
buffer every assembler emits into (`vun_asm::Buffer::new(processor)`). Each assembler emits by the
first form fitting the operands that the processor has (`Op::choose`, `word::Form::choose`,
`Form::needs`); where it has none, the buffer records the need and leaves the instruction out, and
`vun-codegen` turns it into `Missing::Unavailable(Needed)` at the origin of the instruction,
terminator or prologue that emitted it, so every instruction an isel emits, snippet or its own
sequence, is checked in one place and no isel restates a need. The snippet encoder's operand choice
asks the same (`Emits::fits(processor, ..)`). `lang.arch.Need($Feature, $Size)` is declared once and
instantiated by every table (Thumb, arm64 and x86-64, whose `Feature` is empty and whose forms
gained `requires`); sema reads its variants from `lang.arch.Need`. Thumb's isel no longer takes a
convention passing floats in registers for a floating-point unit: the processor says. `Needed::msg`
phrases a need for both `asm.unavailable` and `backend.lacks`
