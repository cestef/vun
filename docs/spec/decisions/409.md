# 409. A `$c` splicing code that has no value at compile time runs where it is

Status: accepted
Where: 03

A `$c` splicing code that has no value at compile time runs where it is spliced, whatever the reason
evaluation stopped, as spec 03 says (`Builder::spliced`): a run-time read, but also a form the
evaluator does not run yet, such as a struct keeping a borrow that a method writes through. Only a
trap the code fires when computed at compile time is reported there, as the evaluation stopped
(decision 73). Before, any reason but a run-time read made the program fail to build with
`backend.unlowered`, so an `assert` of a call with constant arguments broke whenever the evaluator
lacked a form that call used
