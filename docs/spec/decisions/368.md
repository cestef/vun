# 368. A release's manifest is signed and pinned

Status: accepted
Where: 12
Note: the owner left the calls to the agent

A release's manifest is signed and pinned: `release.json.sig`, the raw Ed25519 signature of the
manifest's bytes, is checked against the key `vun` is built with (`vun_build::release::Key`,
`compiler/pkg/build/src/release/key.pub`, `ed25519:<base32>`; `VUN_RELEASES_KEY` names another, for
a mirror signing its own), so the manifest and, through its hashes, every archive are the project's
(the release workflow signs with `openssl pkeyutl` from the `RELEASE_KEY` secret; Ed25519 is
`ring`'s, already built for TLS). An installed toolchain keeps its manifest beside its tree, outside
what the tree hash covers; a project pinning a toolchain records `toolchain := .{ .version, .hash }`
in its lockfile, the hash of the manifest's bytes, which covers every machine's toolchain at once,
as `go.sum` pins a module (`vun_build::lock::Pinned`); a hand-off refuses a manifest the lockfile
does not record (`Uninstalled::Unlocked`) and reinstalls a toolchain installed from another.
`install.sh`'s first toolchain is trusted as the connection is; the `vun toolchain update` it runs
checks the signature
