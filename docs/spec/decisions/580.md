# 580. `vun cover`

Status: accepted
Where: 11
Amended by: 645

`vun cover` (spec 11, section 6) runs a namespace's tests, all in one process, in a program built
covered, and the runner's `--cover` flag writes the flags of `lang.cover.map` the tests set as a
`covered` line before the totals (`std.testing.Covered`, a byte each, which JSON writes as a
string); `vun_driver::testing::Mode::Cover` asks for it. The report is read against the blocks of
the program the tests reach: `vun_mir::Region::of` gives each block of an instantiation its flag and
the origins of its code, from the same hash `Body::covered` marks with, so the table is never
restated. A line is reached when a block holding code written on it ran, a function when its first
block did, and a function of the package's files that no test reaches counts as not reached, so
unexercised code lowers the share. The rows are per file (`covered_file`) and, with `--functions`,
per function (`covered_function`); `--lcov` writes `SF`, `FN`, `FNDA`, `DA` records with counts 0
and 1, a function named by `line:column`. Flags are not counts and collide modulo 8192, so a share
can read high; not yet: counts per region, branches, one lcov file for a workspace, a function's
name
