# 360. Typing says why in generic bodies too

Status: accepted
Where: 02, 13

Typing says why in generic bodies too: a `$` parameter no instantiation binds has no value for the
reason `Unevaluated::Unbound` (it was "known only at run time"), and so has a requirement of an
interface made for a constrained parameter (the value of `W.Error`); a form typing gives up on for
it is left to the body's instantiations, and one an error typing reported explains
(`GaveUp::Reported`) is not silent (`GaveUp::silent`). The reason travels where a form's type
depends on another's: a local bound without a type keeps why (`Typer::locals` holds `Result<Known,
GaveUp>`, a pattern binding each binder with a type or the reason), each use giving up for it; a
form typed by the type its context expects, where that is not known, gives up for the context's
reason (`Typer::expecting`, through blocks, `if` and `match` arms, `unsafe`, attributes, borrows and
`return`, from a declaration's or a function's annotation); a call whose `$` argument reads an
unbound parameter gives up for it; a declaration typed from its value has the reason typing gave up
for (`TypedBody::unevaluated`). A constrained `$W` named as a type has its interface's requirements
as members, typed and evaluated (`Env::required`, shared with frames), as a value of it has. The
verifier checks the plain body of every generic function a program reaches besides its
instantiations (`Program::bodies`), and `vun debug dump types` shows each body once; logs name
places as `path:line:column` (`OriginId::located`)
