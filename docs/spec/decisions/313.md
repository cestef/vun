# 313. A thread's backtrace names the calls that spawned it

Status: accepted
Where: 07
Note: the user asked for it

A thread's backtrace names the calls that spawned it: `Thread.spawn` takes the chain of its caller's
calls (`std.trace.Spawn`, a `Chain` at `calls` and empty below it, so a release build keeps
nothing), the thread's context carries it, and `Thread.run` keeps it in its frame while the thread
runs and points `std.trace.spawner`, a `std.sync.Local(usize)`, at it; the handler writes the
thread's own calls, then `spawned by` and the spawner's. One level only: a thread spawning another
keeps its own spawner's chain in a context that may be freed first
