# 385. Workspaces

Status: accepted
Where: 12
Note: the owner asked for workspaces

Workspaces (spec 12, section 5): a root package's `.members` are directories below it holding
packages, and with it one project: the graph walked for fetching and selection is the root's and
every member's (`Session::member_packages`), a member's project is the workspace listing it
(`Session::project_of`), so its lockfile, `toolchain` and `replace` are the root's; a command given
the root, or no path in it outside a member, acts on each package, the root first; a member holding
no package is `package.missing_member`. A project has one work directory, `.vun/` in its directory
(`Session::work`, `project_dir`): builds, saved queries and editor views (`Session::shown_at`, at
the file's path in the project) of every root file of a package or workspace go there, and a file
outside any package keeps it beside itself. `vun build` or `run` given a file its package's plan
records as a program's root builds that program with the plan's options (`Session::planned`)
