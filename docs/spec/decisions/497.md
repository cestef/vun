# 497. The Cranelift backend

Status: accepted
Amended by: 499

The Cranelift backend (`vun-backend-cranelift`, Cargo features `backend-cranelift`,
`cranelift-x86_64`, `cranelift-arm64`) generates code from LIR through `cranelift-codegen` and
`cranelift-frontend` (external crates, with `target-lexicon`) for ELF on x86_64 and arm64; what it
does not express (inline assembly, naked functions, C records by value, wide integers under the C
convention, float varargs where the rules pass them as integers) is refused as a `Lack` per function
and handed to an assisting backend (`vun_codegen::Assist`, implemented by native) whose code is
linked into the same object; the object assembler moved from native to `vun-codegen` (`Assembly`) so
both write objects alike. It is a registered backend the tests run beside C and native, which must
agree. Cost: the `dist` build grows from 20,210,824 to 25,126,152 bytes (about 4.9 MB), so the size
budget is 28 MiB (27.1 MiB measured on x86_64, 24.0 MiB on arm64); leaving the features out restores
the old size
