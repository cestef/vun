# 361. Property tests run

Status: accepted
Where: 02, 03, 07, 11

Property tests run (spec 11, section 2): a test with parameters is a property, run over
`std.testing.property.cases` cases, each on a thread of its own, with arguments generated from the
parameters' types; `std.testing.gen(T, c)` makes a value by `T`'s `std.testing.Arbitrary`
(`lang.Int` has one, a choice reduced as `wrap` reduces), or for a struct or an enum by reflection,
a variant then each part; values are read from a choice stream (`std.testing.Choices`: seeded
splitmix64, each choice recorded), and the first failing case is shrunk on its choices (shorter
streams, then each choice at 0 or halfway towards it); the search runs quietly and the smallest case
runs once more to report its trap, its arguments written before its line as `name = ` and JSON; the
seed is the FNV-1a hash of the test's name; the line is `{"falsified":{"trapped", "seed", "case",
"shrinks"}}` and the totals count `falsified`. The pieces it needed: `lang.meta.params(F, f)`
describes a function's parameters as `Field`s (name, position, type, attribute values);
`lang.meta.make(T, variant, parts)` and `lang.meta.Parts(T, variant)` make a value from its parts,
the inverse of `part`, MIR building it as the aggregate; `lang.meta.implements(I, T)`; a function or
closure answers `lang.ops.Call`'s requirement itself, `f.call(t)` being `f` called with the items of
`t` (typing through the requirements, `Env::required`, MIR calling `f` directly); a `$` local's
declaration runs nothing, each read being its value; `std.fmt.json.write` writes a struct or enum
without a `Json` as `derive` does, and `derive` writes its parts through `write`;
`std.os.thread.reporting` lets a thread leave its traps to what joins it, each runtime's trap
handler reporting only while it is set
