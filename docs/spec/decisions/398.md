# 398. A place of an argument in a format string is `{}`, written by the argument's

Status: accepted
Where: 3, 10

A place of an argument in a format string is `{}`, written by the argument's `std.fmt.Format`,
`{x}`, by its `std.fmt.Hex`, `{b}`, by its `std.fmt.Binary` (integers in base 16 and 2), or `{?}`,
by its `std.fmt.Debug`: the rows of `fmt.specs`, each naming its interface and its method, which
`print` calls whatever the row, and which `fmt.hole`, shared by `holes`, `pieces` and `parse`,
reads. A specifier may be followed by `:` and a layout, `[[fill]align][width]` with `align` one of
`<`, `>`, `^` (`{:>8}`, `{x:0>4}`, `{:^5}`): `print` writes the argument once into a `Measure`
writer to find its length, then the fill on the sides the alignment says, and the argument; one
longer than its width is written whole `{?}` writes a value as the expression that builds it, as the
compiler shows values (`.some(3)`, `Point{ .x = 1, .y = 2 }`, `(1, true)`, `[1, 2]`, a quoted and
escaped string). `Debug` is derived for a struct or an enum whose parts have it, as `Eq` and `Hash`
are (`#[lang.derive(derive_debug)]`). A constant typed as a borrow that its value is not, a string
literal, is held in a temporary of that type wherever it is an operand, so a literal is an argument
of `print`; a call whose signature fails to evaluate in an instantiation that absorbed its reports
counts an unbound `$` parameter as any other form does
