# 362. Code written in a body is identified by the instantiation evaluating it, not

Status: accepted
Where: 02, 13

Code written in a body is identified by the instantiation evaluating it, not only by the
compile-time call: `Func::within`, `Code::within`, a frame's `within` and a nominal type's identity
hold an `Instantiation` (`$` parameters bound, run-time ones not), and a compile-time call is the
instantiation binding every parameter (`Instance::instantiation`). `Env::inside` evaluates under the
instantiation it binds, so a function literal or closure in `($n: u8, x: u8)` sees `n` once built
and is typed with the instantiation's body, and a `struct` literal there is one type per `n`
(decision 28). A body binding nothing keeps the identity it was evaluated in, so plain bodies are
unchanged. `Instantiation::body` is the instantiation whose typed body a call or instantiation runs,
`Instantiation::call` the compile-time call an instantiation binding every parameter is (what
`made_by` reads a type's constructor arguments from). A MIR temporary holding an expression's value
has the expression's type (a string literal held as the borrow it is typed as, so `d < "0"[0]`
builds)
