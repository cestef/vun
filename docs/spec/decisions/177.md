# 177. Query persistence

Status: accepted
Where: 13
Note: the user's choice of the derive crate and of zero-copy, parallel loading

Query persistence: a query persists its memos with their values (`Db::persist`) or by their traces
alone (`Db::trace`, for values not worth saving, such as parsed files); a traced memo loaded and
verified stands for its value in verifying its dependents, and the value is computed only if read.
Inputs are declared (`Query::INPUT`) and never saved. Values are read from the file loaded when
first needed, keys in parallel; the file is saved only when a memo was computed that it did not
hold, extending the stream loaded so that values never read are written as they were read. Codecs
are derived (`#[derive(Encode, Decode)]`, `vun-codec-derive`, on `proc_macro` alone); a handle into
a process table (`Symbol`, `Interned`, `FileId`, `OriginId`) is `Pooled`: written once per stream by
content and recorded again when read. Files live in `.vun/queries/<toolchain>` beside the root file,
the toolchain named by its executable's path, size and time of change
