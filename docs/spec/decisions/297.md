# 297. A float the backend does not hold

Status: accepted
Where: 04, 13

A float the backend does not hold (`BackendCaps.floats`: every one for a backend handing its code to
a compiler, those the target computes for native code) is held as its bits by legalization, an `f64`
on a 32-bit target two limbs; every operation on it having run as `lang.float.soft`'s, only moves
and bitcasts remain, anything else `Unlegalized::HeldFloat`. A C signature passes one only where the
convention passes floats in general registers (`Rules::of(convention)` now names each convention's
rules once; `Unlegalized::FloatAbi` otherwise). `TargetSpec.floats` (`vun_target::Floats`) is the
one reading of `Spec.floats`, and a processor computing `f32` computes `f16` through it, as
`Half::Promoted` does (the previous commit sent `f16` to the soft routines on every target). An
integer is aligned to its size, one wider than 8 bytes to twice an address at most (`i128` to 8
bytes on 32-bit Arm, as AAPCS aligns no type more); narrower layouts read no target, so they are
known before one is chosen
