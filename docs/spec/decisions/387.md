# 387. Coverage-guided fuzzing

Status: accepted
Where: 11

Coverage-guided fuzzing (spec 11, sections 2 and 6). Coverage is its own input,
`vun_sema::cover::CoverageOf` (`Coverage::Off` or `Blocks`, set by `--cover` and by `vun fuzz`, a
key of the shared memos with the target and checks), not a check: under it the concrete MIR of every
function but a naked one stores 1 at `lang.cover.map[n]` as each block starts, `n` the stable hash
of the instantiation and the block's position modulo `lang.cover.size` (8192), two statements over a
`StaticMut` local, so every backend covers alike. Fuzzing works on choice streams, as properties and
simulations do: `std.testing.fuzz` keeps up to 64 streams whose cases set a flag none before set,
mutates one choice of a kept stream (a value drawn half the time, else 0, the next value, its half,
or a cut) or draws a new stream one case in four, and shrinks a failing case as a property's; the
runner's `--fuzz` flag runs the properties alone over `--cases`, `vun fuzz` defaulting it to 10000,
and a passing one's outcome is `fuzzed(.{ .runs, .kept, .flags })`. The tests' kind is decided once,
`std.testing.kind` (`unit`, `benchmark`, `property`), for both choosing and running a test;
`vun_driver::testing::Mode` (`Test`, `Bench`, `Fuzz`) replaces a flag. The register allocator's
check let a value made again where read (`Remade`) enter a block in no place, which the allocator
plans (`vun_regalloc` check); covered code on arm64 reached it. Not yet: the corpus in `fuzz/`,
traced comparisons, `vun cover`
