# 506. `lang.arch.wasm32` names functions and linker globals in blocks

Status: accepted
Amended by: 509

`lang.arch.wasm32` names functions and linker globals in blocks. `call(f)` takes a symbol operand
(`Kind.symbol`, a `Given::Symbol` as on the other architectures) and its stack effect,
`Scope::Call`, is the function's type: sema reads the signature and fills the pops and pushes (a
stack of an unknown type leaves the rest of the block unchecked), the module verifier reads the
symbol's type; the encoder relocates the index (`FunctionIndexLeb`). `global_get` and `global_set`
take a `Choice.global` (`stack_pointer`), which the backend resolves to the symbol it defines
(`GlobalIndexLeb`); a global the program declares has no Vun form, so only the linker's are named.
`call_indirect` is not offered. | 07, 13
