# 131. `vun` is one executable

Status: accepted
Where: 13
Note: the user's choice

`vun` is one executable: compiled in, what checks, builds and runs a program alone (front end,
checks, MIR, interpreter, `fmt`, LSP, packages, renderers, C and Cranelift backends); heavy native
libraries (libclang for `vun tool bind`, libLLVM for the LLVM backend) loaded on first use through
one adapter crate each, the only crates allowed `unsafe`, never linked in, their absence one
diagnostic; third-party components as processes, never the toolchain's own features; and a decision
per new external crate (the size budget it once set was dropped, decision 499)
