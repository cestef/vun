# 685. `vun check` reports wide intermediates and generic code size on request

Status: proposed
Where: 03, 04, 09, 13

`vun check --widen` lists each arithmetic result (`add`, `sub`, `mul`, `neg`) whose range needs
more bits than the target's register holds (`Target::register_bits`), as a row of where it is
written, its bits and the register's, so a measure never fails a check. `vun check --meta-stats` prints a
row per generic function the program reaches: its instantiations and the MIR statements of all of
them, which stand for generated code size. Both are options of `check` named by the variants of
`vun_driver::reports::Report`, each measure a query (`WideChecks`) or a walk of the program
(`Programs`) giving typed rows, so a new measure is a variant and not a flag threaded through the session. Not
done: evaluation steps per generator, which need the query engine to list the memos of
`MeteredCall`, and grouping by the call site of a generator, which waits for the origin chain
to record splices (`Via::Splice` is built nowhere yet).
