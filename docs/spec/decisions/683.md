# 683. A runtime without a C library has a heap

Status: accepted
Where: 08, 05

A runtime without a C library has a heap: `std.os.heap.pool.exports(reserve, unmap)` exports `take`
and `give` over the pages the runtime already maps for its checks (the kernel's `mmap`, WASI's
`memory.grow`, `VirtualAlloc`). A `Pool` (blocks of 16 to 2048 bytes by powers of two, cut from 64
KiB chunks, a free list per size threaded through the freed blocks; larger requests are pages of
their own, rounded to 4096; alignment past 4096 is `.exhausted`) is held in the critical section and
written without a trap (`#[panic.never]`). `std.os.heap.unsupported` and
`std.os.library.unsupported` are gone: a runtime that loads no library exports none, so a program
loading one does not link (`link.undefined` on WASI, an undefined reference on the kernel).
`lang.mem.grow_memory(pages)` is WebAssembly's `memory.grow` as a primitive (`InstKind::GrowMemory`;
the wasm and C backends express it, the others refuse it with `backend.lacks`), so that the WASI
