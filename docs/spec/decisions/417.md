# 417. A function or function type names a calling convention of the target's

Status: accepted
Where: 07, 13

A function or function type names a calling convention of the target's architecture besides the
target's own by the markers `abi.sysv`, `abi.win64`, `abi.cdecl`, `abi.stdcall`, `abi.fastcall` and
`abi.thiscall` (identity markers, called as C's are), which become `Signature::convention` in LIR,
are written by the C backend as GNU attributes on a prototype and in a function pointer's type, and
are refused by lowering where the architecture has none of that name (`Why::Convention`) and by the
driver for a backend without `Feature::Conventions` (every backend but C, whose help says to build
with `--backend c`). `lang.target.Convention` gains `cdecl`, `stdcall`, `fastcall` and `thiscall`,
whose `Rules` are not built: no backend places arguments for them but the C compiler
