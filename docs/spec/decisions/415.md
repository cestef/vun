# 415. The flags a C compiler takes for the code of a shared library are target data

Status: accepted
Where: 08, 13

The flags a C compiler takes for the code of a shared library are target data,
`lang.target.CCompiler.shared` (`-fPIC` for the GNU rows and macOS, none for Windows), where the
driver once added `-fPIC` for every shared library; the link plan carries the symbols a library
exports (`LinkPlan::exports`, from `lir::Unit::exports`), which the COFF flavor gives `lld-link` as
`/export:` beside `/dll`, since a PE file exports only what it names. A DLL has no runtime to define
the symbols the C compiler assumes (`memcpy`, `__chkstk`, `_fltused`) nor the trap, so the runtime's
services beside its entry are `std.os.windows.services`, which the runtime and a library both hold.
Every symbol a library exports is in its export table, its services among them, as an ELF shared
object's dynamic symbols are
