# 300. The float bank of the register allocator is the home of values no general

Status: accepted
Where: 13

The float bank of the register allocator is the home of values no general register holds: an
architecture says which bank a scalar's values are in (`Arch::bank`, general by default), the float
bank having no registers, so the scan keeps each of its values in its home, sized to the value; the
framework moves such values between homes a word at a time, never makes them where used, and fuses
no comparison of them. Thumb keeps `f64` there where the FPU computes it (linux.arm), each operation
a sequence written by the isel (`Selection::Homed`, `isel/double.rs`) over `d0`/`d1`; a bitcast
between such a float and limbs goes through a slot in legalization. Codegen traces each terminator
and, at debug level, each instruction the backend lacks. The backend tests run on linux.arm where
the toolchain file names a runner
