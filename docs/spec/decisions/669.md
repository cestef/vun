# 669. Machine code is kept per function by content

Status: accepted

Machine code is kept per function by content (spec 13, section 2). Each function is looked up as
lowered, before legalizing, renumbered locally (functions, imports and data in first-met order),
keyed by the stable hash of the toolchain, target, backend and its legalizing, pointer width, the
renumbered function and the kind and signature of each name; relocations are mapped back to the
unit's ids on use. A function whose code is kept is neither legalized (unless its signature changes)
nor compiled; code calling a helper legalizing adds is not kept. Only a backend with
`Feature::Keeps` (native) is given kept code. A program's code is one file per target and profile,
written back with the entries the build used. A warm build or an edit compiles only the functions
that changed (a warm `build-hello`: 248 to 160 M instructions); shipping the code with a primed
toolchain is left, as priming checks and does not build.
