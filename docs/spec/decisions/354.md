# 354. A trap ends its thread

Status: accepted
Where: 07
Note: the owner chose it as the base of the test runner

A trap ends its thread (spec 07, section 3): the execution context is the thread. Each runtime
places how a spawned thread ended (`std.os.thread.Ended`: `returned` or `trapped(lang.panic.Trap)`)
beside its record (`Placed.ended`), points the thread's `std.os.thread.ending` at it when the thread
begins, and its trap handler, after the backtrace, keeps the trap there (`std.os.thread.trapped`)
and ends the thread alone (`pthread_exit`, Linux's `exit` rather than `exit_group`); `std.os.join`
returns the `Ended` and `Thread.join` gives `Result(R, lang.panic.Trap)`. A trap in the thread the
program started in ends the program. No unwinding: `defer` does not run and what the thread held
stays held. The rule isolates tests without test machinery (a process per test, `setjmp`/`longjmp`
and tests only at compile time were turned down) and serves supervisors and servers alike
