# 419. Lowering stops at nothing the front end could say

Status: accepted
Where: 04, 10, 13

Lowering stops at nothing the front end could say: a call of a function of `$` parameters alone that
gives an integer is that integer in MIR (`Body::fold`), as typing took it, so a result like
`Int(1..)` that has no storage is never a run-time value; a member of an impl that its interface
names no requirement of is untyped where its parameters are (`types.untyped_param`), not given up on
silently; a file a program reaches has its names reported with its syntax and lints, unless it
failed to parse; a trap a `$` form fires in library code reached while lowering is shown as
`lang.diag.error` is at compile time; the type narrowing brings a value into is bound by
`std.int.Integer`; an address made into a type that is no function type says so, a method taking its
receiver by value is called with the value a borrow reaches where the receiver is one (`b.try_to(T)`
of a `b` borrowing a `u8`), and `lang.trace.Detail` compares at run time. `corpus` lowers every
function it reaches (3219 of 3219)
