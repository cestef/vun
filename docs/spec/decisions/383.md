# 383. Generic bodies are not typed abstractly

Status: accepted
Where: 02

Generic bodies are not typed abstractly: an unconstrained `$T: type` and a requirement's value
(`W.Error`) stay unknown in the generic body, whose forms needing them are checked per instantiation
(spec 02, section 3; decision 360), rather than given opaque types with every compile-time
evaluation reading one deferring. A `$` value is a compile-time value like any other, which a body
computes with (`$if`, `$for`, reflection), so an opaque stand-in could type only the bodies that
never inspect it, and a second typing of those would disagree with the instantiation's wherever
evaluation decides. What an abstract check would add, errors in generic code no program
instantiates, tests give by instantiating it
