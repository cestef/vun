# 326. A program's build places its sections

Status: accepted
Where: 08, 12, 13

A program's build places its sections: `std.build.Options.sections` is a list of
`std.build.Placement` (a section, the region holding it, the region it loads from if another) beside
`memory`, which a board's package provides (`stm32f4.layout.memory`, `.sections`); the link plan
carries them, and the linker script defines, per the one rule of `vun_link::Bound`,
`__<section>_start`, `__<section>_end`, `__<section>_load` for a section loaded elsewhere, and
`__<region>_end`, which a runtime declares as link symbols. Bare-metal targets link through their C
compiler's linker (`.gnu`), which places sections; the `stm32f4` runtime's reset handler copies
`.data` and zeroes `.bss` from those symbols, its vector table starts the stack at `&__ram_end`, and
