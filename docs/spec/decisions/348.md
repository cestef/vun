# 348. Measuring speed, permanently

Status: accepted
Where: 13
Note: the owner asked for benchmarks and permanent tooling

Measuring speed, permanently: criterion benchmarks (`cargo bench`) of lexing and parsing the
repository's sources (`vun-syntax`) and of the compiler end to end over corpus programs
(`vun-driver`: from nothing, from saved memos, after an edit), compared against saved baselines;
`--timeline <file>` (`VUN_TIMELINE`) writes every run of each timed activity, per thread, in the
Trace Event Format Perfetto opens, and the timings report each activity's longest run, a caller
waiting for the workers of its `par_map` (`wait for workers`, `vun-par` timing through `vun-trace`
now) and each query's saved values read (`read <query>`); finding the project, fetching and writing
the lockfile are timed stages. Faster: a first compile parses its package graph ahead over threads
once the root's package is published (it parsed nothing ahead before), verifying ahead spreads over
threads only the outermost reads, and a package's files are read and hashed over threads. The
grammar's derived facts (automata, operands, first tokens, leading positions and closures,
preferences, the kinds each token starts or makes transparent) are derived once, in one value, each
from those before it, among them each kind's opening (the tokens and words it may start with where
no operand was read, and so the kinds each token opens), and a candidate of a reading holds its
automaton. A file of shared memos is written once, by a database that loaded none: one that loaded a
shared file saves the shared memos that file lacks with its own, layered over it, never writing the
shared file whole again; memos just saved are layered under the database by the places the save gave
their keys, nothing read back. `cargo xtask remote --reserve` runs on the host's cores of the
highest capacity (`cpu_capacity`), its services (`system.slice`) confined to the others meanwhile by
a runtime property of systemd
