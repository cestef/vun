# 498. The parts of the toolchain are components

Status: accepted

The parts of the toolchain are components (backends and linkers, and any kind a crate declares an
interface for, a kind being a name), provided linked into `vun` (a Cargo feature) or loaded from a
dynamic library of the toolchain's `components/` directory, through one typed interface (the
`Backend`, `Linker`, `Scheme`, `Server`, `Binder`, `Formatter`, `Documenter` and `Renderer` traits;
a URL scheme such as `https`, with its TLS stack, is a component of the `minimal` profile, a server
such as the language server, a program run until its client leaves over the process's standard
streams, one of the `default` profile, as is the C binder, which loads libclang when it binds, the
formatter of Vun source (`minimal`), the HTML documenter (`default`), which asks the host which
declarations declare a type, and the diagnostic renderers `terminal` (`minimal`) and `ariadne`,
which read the diagnostic's origins and files from what crosses, and ask the host only where a file
was read again; the one-line renderer stays linked as the fallback) so that the crate is the same
either way, and the first registered of a name is used (a backend that cannot express everything is
assisted by the request's `Assist`, which the host answers with the first registered backend that
has `Feature::Assist`, native, so that a library does not carry another's code); a loaded component
is reached through a single C-ABI call carrying `vun-codec` messages with a host call the other way
(source lines, and the library's timings, which the host times in its own table nested under the
call, each call being a `component` activity), so no Rust type, allocation or static crosses it, a
panic is `component.failed`, a library of another layout or release is `component.invalid`; the
loader and the exporting macro are the `unsafe` exception, with the soundness argument written
beside them; a release lists each component's archive per machine with its tree's hash in the signed
manifest, each in the smallest profile (`minimal`, `default`, `full`) that holds it, a component
names the components it cannot work without (`needs`), which the manifest carries per piece and
installing it brings, and a library's timings reach the host's table on every thread; a toolchain
loads only the libraries its kept manifest names; `vun toolchain install --profile`, `component
list\|add\|remove` and `.components` pin them; the release's `vun` (`dist` feature) links only the
planned stubs and every ready backend, linker, scheme, server, binder, formatter, documenter and
renderer is a library built from `compiler/components/<kind>-<id>`, or `compiler/tools/<kind>-<id>`
for a server, binder, formatter or documenter with the `export` feature
