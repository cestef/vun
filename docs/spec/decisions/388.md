# 388. The wasm target links in process

Status: accepted
Where: 13

The wasm target links in process (spec 13, section 8.4). `vun-link-wasm` is the linker `wasm` and
`wasi.wasm32.p1`'s, in place of `wasm-ld` (still `--linker lld`): objects of the tool conventions,
the wasm backend's and clang's, resolve strong over weak and the first COMDAT group over later ones;
what the entry, the exports and the kept symbols do not reach is left out; the stack comes first in
memory (1 MiB, since `wasm-ld`'s 64 KiB is too small), then `.rodata`, `.data`, named sections and
`.bss`, a section of zeros unwritten; the linker defines what `wasm-ld` does (`__wasm_call_ctors`,
`__heap_base`, `__start_<section>`, ...) and the plan's bounds; an undefined weak function traps
when called. The encoding and the object reader are one crate, `vun-wasm`, which the backend writes
with. The backend now places data in sections, gives storage per thread as the program's on
one-thread targets, and calls C variadic functions through clang's buffer. Refused still: inline
assembly, naked functions, addresses past a function's start
