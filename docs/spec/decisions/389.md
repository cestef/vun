# 389. The compiler runs under WASI

Status: accepted
Where: 12, 13

The compiler runs under WASI (spec 12, section 6): `vun` builds for `wasm32-wasip1` with the
platform's absences decided where they arise, by target, not by feature: the user's directories are
`vun_build::dirs::Dirs::user`, none under WASI (`etcetera` is left out there), so the store is the
working directory's and the tools file only `VUN_TOOLS`'s; a process is told apart by
`vun_fs::PROCESS`, random under WASI, whose `std::process::id` panics; `vun ffi` and its libclang,
and mimalloc, are left out of the CLI there; `vun-bind` is a dev-dependency of the driver, which its
tests alone use; the main thread's stack is 8 MiB (`.cargo/config.toml`), as the pool runs its work
there. Where no thread starts (`vun_par::SPAWNS`), the language server's loop reads each message
itself (spec 13, section 11). The playground (`site/play.html`) runs `vun build main.vun -o
main.wasm --format json` in a worker through a WASI shim, the library at `/lib` from
`play/library.json`, then the program with a directory `.` of its own; the records are drawn as
cards (places selecting the editor's text, fixes applied to it, explanation pages from the library).
Its editor (CodeMirror, Helix's keys on request) is served by `vun util lsp` in a second worker,
whose standard input waits on shared memory, so the page is isolated across origins (`_headers`);
share links are deflated with a preset dictionary of corpus programs, versioned by their first
character. The running compiler is `vun_fs::EXECUTABLE`, the platform's answer or, where WASI gives
none, the path of its first argument, and one identity names it everywhere
(`vun_query::Build::identity`: its path, size and time of change, for the memos' stamp, the queries
file and the shared directory, where the driver hashed its own before). The playground lays the
toolchain out as a release unpacks, `toolchain/<build>/bin/vun` beside `lib/`, so the library is
found beside it and its memos, kept in the worker's filesystem between runs and in IndexedDB between
visits, are its own: a build of hello goes from 1.6 s to 0.1 s
