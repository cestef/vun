# 367. Toolchains are installed, pinned and updated as Go's are, with no launcher apart

Status: accepted
Where: 12
Note: the user chose the model

Toolchains are installed, pinned and updated as Go's are, with no launcher apart: a release, tagged
with its version as it is, carries `release.json` (`vun_build::release::{Release, Build}`,
`vun-data` JSON; a `Machine`, the archive `vun-<arch>-<os>.tar.gz`, gzip so every system unpacks it,
and the BLAKE3 Merkle hash of the unpacked tree `bin/`, `lib/`, `LICENSES/`, as packages are
hashed); releases are found under the repository the workspace declares (`repository`,
`CARGO_PKG_REPOSITORY`) or `VUN_RELEASES`, laid out as a forge's (`Releases`); toolchains live in
`~/.local/share/vun/toolchains/<version>/` (`Toolchains`), the default linked as `~/.local/bin/vun`;
`vun toolchain list|install [version] [--default]|remove|update` (`Session::install`: fetched
through the session's schemes, unpacked beside the others, checked, moved in; `Uninstalled` typed,
`toolchain.install_failed`, `not_installed`, `in_use`); a project's `.toolchain` makes a `vun`
loading it install that version when missing and replace itself with it (`Session::hand_off`, the
child run with `VUN_TOOLCHAIN=local`, which also opts out); `cargo xtask package` packs a built
`vun` as this machine's archive and `cargo xtask release` writes the manifest after checking the
tag, which `.github/workflows/release.yml` runs into a draft release; `install.sh` unpacks the
latest archive and lets it run `vun toolchain update`. `vun-data` gains `textual!` (a type as its
text form), used for `Hash` and `Version`; `Name` and `Machine` are data. The lockfile does not
record the pinned toolchain's hash yet
