# 686. A link symbol with a pack is imported as a variadic C function

Status: proposed
Where: 07, 13

A link symbol with `$` parameters that ends in a pack (decision 514) is imported as a function, not as
data: its LIR signature is the parameters before the pack that are no `$` ones, and its result, with
`Signature::variadic` marking where its calls' items start and none given. Each call keeps its own
signature through the symbol's address (`Callee::Indirect`), since the items differ per call. It was
data, so the C backend declared it `extern u8 name;`, which a link of position-independent code
refuses for a function; it is now declared with its prototype and `...`. A `$` parameter ending in
no pack, a parameter or result type naming a `$` parameter, or a convention other than C refuses the
program (`Form::Import`). `Callable::fixed` reads what the declaration states apart from its calls.
