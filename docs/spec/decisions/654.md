# 654. Backends agree on a program when their runs have one outcome, not one process

Status: accepted
Where: 11, 13

Backends agree on a program when their runs have one outcome, not one process status. How a run
ended is a typed `Ending` (`Returned(code)`, `Trapped`, `Crashed(signal)`): every signal a trap uses
(`ud2`, `brk`, `abort`, an arithmetic fault) is `Trapped`, so backends may trap differently, and a
fault of the memory is not a trap. What a run wrote is compared by a policy of the stream and the
ending: all of it when the program returned; for a trapped or crashed one, stdout up to the shorter
run (buffered output is lost at a trap) and stderr not at all (its words are each backend's own).
The reference is the run most of the runs agree with, not the first backend, so a fault of one
backend is blamed on that one. Rather than comparing exit codes, lossy-decoded lines and the first
backend, which blamed the others for a fault of the first and could not tell a trap from a crash
