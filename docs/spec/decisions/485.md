# 485. `lang.mem.Uninit(T)` and `lang.mem.uninit(T)`

Status: accepted
Where: 05

`lang.mem.Uninit(T)` and `lang.mem.uninit(T)`: storage with the layout of a `T` and no value in it,
copy and free whatever `T` is (it owns nothing, so a linear value written into it is the writer's to
account for), made without writing a byte and never known when compiling; a `T` is read out through
`lang.mem.cast` and `read`, `unsafe`. `std.collections.ArrayVec(n, T)` is `[n]Uninit(T)` and a
length, linear as `Vec` is, so a vector of linear items cannot be copied into two owners. Rather
than `[n]?T` (a tag per item, filled with `.none`) or a fill value passed to `empty` (every `T` has
none), and rather than `Uninit(T)` taking `T`'s kind: a linear `Uninit(T)` could not be discarded
without a `forget` primitive, the cost being that its items are not dropped, as a `Vec`'s are not
