# 355. Tests run as a program the library makes

Status: accepted
Where: 11, 12, 03, 07
Note: the owner chose the program's roots over a generated root file or a plan output

Tests run as a program the library makes (spec 11): `std.testing.runner(ns)` gives the exports of a
program running each `#[test]` of `ns` and the namespaces in it (`std.meta.collect`) on a thread of
its own, joining it for the trap that ended it (354), and writing a JSON line per test
(`std.testing.Line`, written by `std.fmt.json.derive`, the reflection-derived JSON writer of
`std.fmt.json`) and one of the totals; its arguments filter tests by name. A program's roots are a
root file's exports or the members of a type (`vun_mir::Roots::Members`), so `vun test [path]
[names]...` needs no source naming the runner: the driver calls it at compile time by its handle
with the namespace of a file, a directory or a package's directory as a value
(`vun_sema::testing::Runner`), builds the members' exports and reads the lines as
`vun_driver::testing::Line`. `vun-data`'s derive writes an enum with fields tagged, `{"variant":
value}`, as `std.fmt.json` does. A pointer into a cell has no value at compile time (a run-time
place), so an assertion over a global `Atomic` runs at run time; a failed assertion's trap site is
its condition
