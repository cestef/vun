# 350. Diagnostics are written to one rule

Status: accepted
Where: 10
Note: the owner asked for better diagnostics, help and fixes

Diagnostics are written to one rule (spec 10, section 2, *Writing a diagnostic*): the message says
what is wrong in the source's terms, never a compiler stage; the primary label marks what is there,
secondary labels the other places involved; every error and warning says what to do, with a fix
carrying a determined change at an honest safety; a note states the rule. `vun fix <file>
[--unsafe]` applies fixes (`vun_driver::fix`): per diagnostic the preferred admitted fix, no
overlapping edit, rounds to a fixed point of at most four, a file whose fixes add errors restored;
the rejected corpus is fixed in a test that requires no added error and a fixed point.
`Diagnostic::warning`, `help`, `note`, `Fix::insert`, `remove` and `preferred` are the builders
