# 684. The command line has a closed vocabulary of verbs

Status: proposed
Where: 12

A leaf command of `vun` is named by a `CommandVerb` (`vun_command`), a closed table giving each verb
one name, one meaning and one `Kind`: `Read` leaves the user's files, packages and settings as they
were (caches do not count), `Write` changes them. `Command::run` takes a `CommandVerb`; a command
named by what it acts on (the views under `vun debug dump`) is a `Command::item` and may sit only
below a group named by a verb (`Command::verb_group`). `Command::verify` walks a tree and reports
a leaf outside the table and a name two siblings answer to; the test suite runs it on the `vun`
tree. A new verb is a new table entry with its meaning, reviewed as a design change.

`completion`, `lsp`, `coverage`, `queries`, `profile` and `smith` are nouns the tree already used as
leaf names; they are table entries so that no command is renamed, and a later rename may remove
them. The table marks each entry `Standing::Verb` or `Standing::Legacy`, and `CommandVerb::legacy()`
lists the six, so a test pins the set and a rename shows as a deletion. `cargo xtask` and `cargo gen` name their tasks freely and are not checked.
