# 299. `lang.target.Spec.register_bits`, a general register's width, is the widest

Status: accepted
Where: 13

`lang.target.Spec.register_bits`, a general register's width, is the widest integer the processor
computes with: `Target::computes` and so `lower.soft` read it (not the address width: wasm32
computes `i64`), and the native backend's widest integer is it (`Widest::Register`). The C backend
passes a wide integer's limbs as parameters of their own under Vun's convention and a wide result as
a record of them, joining two limbs into one C integer only under the C convention (`__int128` on
64-bit targets alone), so it builds for 32-bit Arm; the Thumb copies and fills of
`std.os.linux.kernel.memory` bind their operands to the registers they use, which the C backend
needs, having only the argument registers for bindings
