# 306. Threads

Status: accepted
Where: 08, 13
Note: the user asked for kernel threads

Threads: `System.spawn(&mut f)` gives a linear `std.os.thread.Thread(R, F)` tied to the closure's
borrow, joined for what the closure returned; runtimes export `std.os.symbols.{spawn, join}`, taking
a `std.os.thread.Start` and a copy of the thread's context: the kernel runtime maps an 8 MiB stack
with a 64 KiB guard, calls `clone` and joins by `futex` on the id the kernel clears, the C library's
calls `pthread_create`/`pthread_join`, WASI's reports `Error.unsupported`; no thread-local storage
yet; the new thread branches from `clone` to the function its stack names through no register the
call does not read (a block the assembly checks watch keeps two free) and, on arm64, through `x16`,
which branch target enforcement lets land on a function's entry; x86_64's table gains the indirect
`jmp`. MIR empties blocks control never reaches (code after a `return` in a match arm assigned `()`
to the arm's value)
