# 349. The language server shows every representation the compiler builds and uses

Status: accepted
Where: 13
Note: the owner asked for IR views, compile-time views, run and test lenses and layout inlays, then for inlay hints showing types only; test lenses wait for a test runner

The language server shows every representation the compiler builds and uses what sema computes:
views are one table in the driver (`vun_driver::view::View`: tokens, cst, manifest, plan, hir,
types, values, mir, layout, program, lir, code, frames), each with what it is a view of (any file, a
package's `build.vun`, a program a root file exports), which `vun debug dump <view>` prints and the
server offers as `source` code actions; executing one (`workspace/executeCommand`, command
`vun.view`) writes it beside the file (`.vun/views/<file>.<view>`) and asks the client to show it
(`window/showDocument`). Each declaration of a root file exporting its program carries a lens
running it (`vun.run`: built, run without input, its output written to `.vun/views/<file>.run` as it
comes and shown). A hover on a declaration's own name shows the declaration; any hover shows `name:
T = value` (the value when compiling computes one other than a function or type literal written: the
declaration's, or else the expression's own, query `ExprValue`), the stage, the layout of the type
hovered or of its type, and the doc comment. Struct values print their fields as a literal writes
them
