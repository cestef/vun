# 652. A tail call reuses what its caller received instead of needing registers alone

Status: accepted
Where: 09, 13

A tail call reuses what its caller received instead of needing registers alone. Its stack arguments
are written over the caller's own, staged in the outgoing area first since a value passed may be
read from there (`Passing::replaces`: no more bytes, no record the convention copies into the
frame); a record in memory of Vun's convention, passed by the address of a slot of the frame being
left, goes in the memory the caller received for one of its own (lowering, `reuse_received`: the
first not taken that holds it); a result in memory is written through the caller's own address,
which LIR verifies (`Reason::Tail`); wasm passes its copies of C records over the caller's
(`Passing::reuse`), and the C backend refuses a tail call with a record over the registers' size as
an argument or a struct or wide integer as a result, which GCC's `musttail` rejects. Rather than
refusing every record in memory at lowering: that was sound only because nothing passed by address
could reach a callee, while here native and wasm would hand the callee an address into a frame it
overwrites. Fixed on the way: a `musttail` statement after a label was printed as the label's
attribute, which GCC ignores (no guarantee) and Clang rejects, so it is printed in a block
