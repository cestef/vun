# 268. Unsafe code can be checked at run time, by kind

Status: accepted
Where: 07, 13

Unsafe code can be checked at run time, by kind (`lang.check.Kind`: `pointers`, `allocations`,
`asm`), as a program's build options choose (`std.build.Options.checks`, `--checks`): operations
marked `#[lang.check.by(kind, f)]` (the `lang.mem` pointer primitives, and the `Allocator`
requirements) run as their checked Vun versions when a function is made concrete; lowering gives
slots whose address becomes a raw pointer redzones, and poisons them on return; the native backend
checks the memory an asm block writes and the stack pointer it returns with; the state is shadow
memory in the runtime, reached through typed link symbols in `lang.check`. Fat pointers are rejected
because they break layouts and C interop; a failed check is a trap site with a typed
`lang.check.Violation`, reported with its origin. Past the shadow, the runtime keeps a table of what
allocators hand out (`foreign_free`, `size_mismatch`) and a bounded quarantine
(`lang.check.quarantine` bytes) holding memory given back, poisoned, before the allocator gets it:
memory leaves it only for the allocator freeing at that moment, so it never goes to an allocator no
longer alive.
