# 340. The parser reads the productions of `nodes.vun` and replaces the hand parser

Status: accepted
Where: 13

The parser reads the productions of `nodes.vun` and replaces the hand parser: each production is an
automaton over its terms (`vun_grammar::Automaton`), and a stack of readings and operands reads the
tokens, a reading keeping every kind the node may still be at its positions, a child read once for
every position reading it, the node's kind chosen when the tree is written from what the position
holding it takes along the path its reading took. One rule says who reads a token (the outermost
reading reading it where it stands, every frame above able to end; else the innermost operand a form
continues, by level and the longest run of leading tokens); recovery supposes, completes or skips,
and after a report stays quiet until a production reads punctuation in place (spec 13, section 5).
The grammar changes with it, the edge cases going: `.ending` folds into `.of` (a `transparent` node
stands for what it ends with wherever a table names kinds), doc comments and attributes are
`transparent`, a token no production reads is a `skipped` leaf in no field, `fields` names the
entries a `,` ends, a `$for`/`$if` entry of a list is a `staged` node (`.staged("$", .of(.control,
staged_forms))`), files and `struct` bodies hold declarations only (`run();` at file level is
reported where `:=` is expected), a selection holds names, borrow qualifiers and modes follow `&`
only, `defer` is at the loosest level and takes an assignment, a pattern may bind the whole value
(`n := .some(x) =>`), and `.asm {` after an operand is a block wherever it is written (`if c.asm {`,
until assembly is reworked)
