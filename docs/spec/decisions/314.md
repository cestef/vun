# 314. How a platform reaches storage per thread is part of its calling convention

Status: accepted
Where: 07
Note: the user asked for Mach-O's model

How a platform reaches storage per thread is part of its calling convention
(`vun_abi::Convention::thread`: `Thread { access, address, overwrites }`, `Access` one of
`Descriptor`, ELF's TLS descriptor, `Variable`, Mach-O's thread-local variable, and `Offset`, the
linker's offset in a word beside the code), rather than a constant per architecture, since arm64
reaches it one way on ELF and another on Mach-O and the convention is what instruction selection
reads of the target. On Mach-O each per-thread symbol gets a descriptor in `__thread_vars`
(`Object::thread_variables`: `_tlv_bootstrap`, a key, the initial bytes named `name$tlv$init`),
which the symbol then names; arm64 loads its address (`Via::Variable`,
`ARM64_RELOC_TLVP_LOAD_PAGE21`, `_PAGEOFF12`) and calls the function it holds, which keeps every
register but `x0`, `x16`, `x17` and `lr`. Checked by linking with `ld64.lld`; not yet run on a Mac
