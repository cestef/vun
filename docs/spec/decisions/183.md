# 183. The native backend is layered as TPDE is, one crate per layer

Status: accepted
Where: 13
Note: the user's choices: crates, own table, yaxpeax checks

The native backend is layered as TPDE is, one crate per layer: `vun-asm` (code buffers, labels and
fixups per architecture, relocations, immediates, listings), `vun-asm-x86_64` and `vun-asm-arm64`
(each architecture's instructions as one table of forms, which the encoder, the printer and form
selection read, checked form by form against yaxpeax decoders in tests only), `vun-object` (objects
as data, arch-neutral relocation kinds), `vun-codegen` (the framework: assignments, registers,
frames, jumps, fusion, callee-saved registers for loops, and the snippet encoder, through the `Arch`
and `Isel` traits) and `vun-backend-native` (conventions, snippets and instruction compilers per
architecture). Operations are snippets: instruction sequences as data over operand, result, scratch,
fixed and through-register slots, encoded by choosing operands as forms allow and omitting moves of
dying operands; `vun debug code --backend native` lists the code under its source lines
(`Emits::Listing`)
