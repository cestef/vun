# 308. A target lists what its processor has of its instruction set beyond what every

Status: accepted
Where: 07, 13

A target lists what its processor has of its instruction set beyond what every processor of it has:
`lang.target.Spec.features: &[lang.meta.Name]`, read by `lang.target.has(.feature)` at compile time;
`targets.linux.arm` is Armv7-A with division in hardware (`&[.application, .divide]`, built
`-march=armv7ve`, as the native isel emits `sdiv`), the Cortex-M targets `&[.microcontroller,
.divide]`, `macos.arm64` `&[.lse]` (Apple silicon is Armv8.5), the other arm64 targets none. A table
form, or one of its widths, names what it needs (`requires: ?Need`, `Need := enum {
feature(Feature), float(Size) }`, a float width read against `Spec.floats`, never a second list of
it): on Thumb `ldrexd`/`strexd` need `application`, `mrs`/`msr` of a special register other than
`apsr` `microcontroller` (their forms split by `Specials`), `sdiv`/`udiv` `divide`, every
floating-point form a unit computing `f32` and each double-precision width one computing `f64`; on
arm64 the LSE families (`ldadd*`, `swp*`, `stadd*`, `cas*`) `lse`; x86-64's forms are all baseline.
Sema checks a block against the whole table whatever the target, recording what its forms need
(`vun_inline::Block.needs`), and lowering refuses a block of the target's instruction set needing
what the target lacks (`asm.unavailable`). LLVM's assembler is the oracle, through
`vun_harness::llvm` (its exit status and the object it writes, read with the new `vun-elf`, never
its text): for five Thumb processors every form is encoded as the table does where the processor has
what it needs and refused alone where it lacks something; Armv8.0 takes every arm64 form needing
nothing and refuses each needing `lse`. `lang.mem.soft` pairs words only where the target has
`application`
