# 358. Calls and `$` arguments, three gaps closed without a new rule

Status: accepted
Where: 02, 13

Calls and `$` arguments, three gaps closed without a new rule: a borrow of a function or closure is
called as what it borrows (`h()` for `h: &mut F`, spec 02, section 4), typing taking the signature
through borrows and MIR calling `h.*`; a `$` parameter implements the interface its constraint
makes, with that constraint's arguments (`Ty::implements` reads a parameter's interface as it reads
a frame's), so `R` of `$F: Call((), R)` is inferred inside a generic body; a tuple evaluated where a
type is expected is that type (`Env::eval_as`), as typing reads it, so `()` passed to `$R: type` is
the unit type. A body left with an untyped local is reported where the local is, with typing's own
error when it reported one (a library's bodies are reported only as a program reaches them), and
otherwise as a compiler bug naming `vun debug dump mir`
