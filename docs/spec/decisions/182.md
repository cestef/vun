# 182. Backends are chosen by profile

Status: accepted
Where: 13
Note: the user's choices

Backends are chosen by profile: a target lists its backends per profile, most preferred first
(`lang.target.Backends { debug, release }`, replacing `default_backend`; `default_linker` is
`linker`), and a build takes the first the toolchain has that generates code for the target's
architecture (`Registry::choose`, reasons typed as `Unfit::{Absent, Planned, Arch}`); `--release`
chooses the release profile and adds the C compiler's `optimize` flags
(`lang.target.CCompiler.optimize`); `--backend` names one, refused with `backend.unavailable` or the
new `backend.unsupported`, and a target none of whose preferences fit reports the new
`backend.unchosen`. `Backend::emit` takes one `Request` (unit, target, lines, profile, listing). The
baseline backend is renamed `native`, the process backend and linker `external`
