# 667. A toolchain ships the libraries' memos

Status: accepted

A toolchain ships the libraries' memos. `vun toolchain prime` checks every source file of `lang`,
`std` and `targets` as the dependencies of a program with nothing in it, so that their memos are
shared, and keeps them in the toolchain's tree, `memos/`, laid out as the store's `memos` is
(`<toolchain>/<target and checks>/<file>`); `cargo xtask package` and `install` run it on the staged
executable before the tree is hashed, so the release hash covers the memos. A session reads its own
shared files first and the toolchain's after (`Session::shipped`), never writes the toolchain's, and
layers a project's memos over the file it loaded wherever it is. The first check of a program on a
primed toolchain starts from the libraries checked: `hello` takes 70 ms and 0.7 G instructions,
against 500 ms and 4.7 G from nothing. Priming does not cover generic code the libraries lack
instances of, which a program computes and saves as before.
