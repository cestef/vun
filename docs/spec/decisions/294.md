# 294. Floats a processor does not compute are Vun

Status: accepted
Where: 01, 04, 13

Floats a processor does not compute are Vun: `lang.target.Spec.floats` lists the float types a
target's processor computes (linux, macos and wasi all four machines `f32` and `f64`,
`bare.cortex_m4f` `f32`, `bare.cortex_m3` and `bare.rv32imc` none), and `#[lang.lower.soft(f)]` on a
primitive makes each run-time call of it whose first argument is a float type the target does not
compute a call of `f` when its caller is made concrete (`Target::computes`).
`lang.float.soft.arith.{add, sub, mul, div}` and `lang.float.soft.compare.{equal, unequal, less,
less_equal, greater, greater_equal}` compute over the encoding, bit for bit as IEEE 754 instructions
do (the canonical NaN for a NaN result). A sequence of types is read by what is expected of it:
`&[f32]` is a borrow type where a type is expected and borrows the array holding `f32` where a
borrow of types is (`floats: &[type]`), as a tuple of types is a type only where one is expected;
`Value::literal` spells a primitive type by its declaration's path, applied to its arguments
(`lang.Float(32)`)
