# 391. `naming.case` decides what a declaration binds by how it is written, never by

Status: accepted
Where: 10
Note: the user's approval

`naming.case` decides what a declaration binds by how it is written, never by evaluating it (spec
10, section 5): a type when annotated `type`, `lang.Interface` or a function type giving one, or
when its value is a `struct` that is no namespace, an `enum`, a function type, an `interface` or a
function literal giving a type; any other value is a value. An alias of a type, `Index :=
Int(0..9)`, `Error := Full`, or a tuple of types, `Nothing := ()`, is annotated (`Index: type =
...`), as an interface's type member already is. Ends the case of `Error := ()` in an impl being
named as a value by evaluation, and the lint reading `DeclValue`
