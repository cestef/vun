# 312. Storage per thread is a property of a type

Status: accepted
Where: 05, 07, 08, 13
Note: the user asked for thread-local storage, for executables and libraries

Storage per thread is a property of a type: `#[thread.local]` (`lang.thread.local`, on types) gives
every top-level binding of the type one storage per thread, starting as the binding's value, whose
borrows are scoped (never `&static`); `std.sync.Local(T)` is the marked type, reached by value
(`get`, `set`, `replace`, `update`) through relaxed atomic accesses, safe without `unsafe` since no
two threads share a storage and a signal or interrupt handler cannot tear a value. Rather than an
attribute on a `mut` binding, which every access would reach through `unsafe` and which could be
forgotten at a declaration. `lang.target.Spec.threads` (`Threads`: `one`, `many`) says whether a
target runs threads; where it runs one, the storage is the program's. LIR data has a storage class
(`Storage::Thread`) and `thread_addr` takes its address (`addr` of it is malformed); C writes
`__thread`; native x86-64 and arm64 use the TLS descriptor sequence (`Via::Descriptor`, the call
marked `TlsDescCall`, `fs` as a memory base, `tpidr_el0`), which linkers rewrite into the thread
pointer's offset in an executable, so shared libraries and executables share it; 32-bit Arm's native
backend, which reaches what the linker places by address and so builds executables alone, loads the
storage's offset from the thread pointer (`R_ARM_TLS_LE32`) from a word beside the code, branched
around (`Buffer::word`; the Thumb table's `ldr` of a label, `Branch::literal`), and adds the pointer
`mrc` reads (`mrc p15, 0, r1, c13, c0, 3`, its operands the table's `Coprocessor` and `Cr`), rather
than a pool at the function's end, which a function past 4 KiB would put out of reach; a relocation
naming storage per thread names a local symbol of it, never its section's, which linkers read as an
address. The kernel runtime lays out each thread's block from the TLS segment the auxiliary vector
leads to and sets its pointer (`arch_prctl`, `tpidr_el0`, `set_tls`), each thread its own as the
first thing it does, rather than through `CLONE_SETTLS`, whose argument would leave a checked block
of assembly around `clone` too few registers. On the way, a path to a top-level binding (`ns.name`)
resolves to its declaration and reaches its storage, as its name does
