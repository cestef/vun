# 416. A program loads libraries as it runs

Status: accepted
Where: 05, 08

A program loads libraries as it runs: `System.load(path)` gives a `std.os.library.Library`, whose
`unsafe function(F, name)` is a symbol it exports as a function of the type `F`, made of its address
by `lang.mem.function_at(F, address)` (unsafe; lowered as `pointer_at` is, refused for a type that
is no function), and whose `close` unloads it. A runtime reaches the loader through three typed link
symbols (`std.os.library.symbols`), which the C library's runtime serves with `dlopen`, `dlsym` and
`dlclose` (its row's `load` the `dlopen` flags), the Windows runtime with `LoadLibraryW`,
`GetProcAddress` and `FreeLibrary`, and the kernel and WASI runtimes with
`std.os.library.unsupported`. The loader's failures are one `std.os.Error.unresolved`, which the C
library reports as text and Windows as numbers `std` does not tell apart
