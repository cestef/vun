# 381. A plain name in a pattern always binds

Status: accepted
Where: 01, 10

A plain name in a pattern always binds (spec 01, section 6), even where it names a constant around
the pattern: comparing by name would make a pattern's meaning depend on what the prelude and
libraries declare, which adding a name must never change. A constant is compared with when written
as anything but a plain name (`.true`, `limits.max`, a literal). `lang.lint.Local` tells whether a
pattern testing a value binds the local (`tests`: a `match` arm's, an `if` or `for` test's) and
whether it hides a constant (`hides`: its name names, outside the file, data a pattern compares
with, `Value::is_datum`, found through `Env::outside`); the lint `std.lints.suspicious.shadowing`
(warn) reports a local that does both. A binder hiding a function, a type or a namespace is not
reported: nothing compares with one (the corpus prelude's `node` beside `.some(node)`)
