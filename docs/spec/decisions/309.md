# 309. Backtraces

Status: accepted
Where: 07, 08, 13
Note: the user asked for backtraces, inlined frames and violations named, and the table configurable

Backtraces: `lang.trace` declares the table of a program's code (`Table`, `Function`, `Site`,
`Origin`, `Text`); a runtime declares its link symbol (`std.trace.table`), lowering makes the datum
and records the declared layout (`vun_lir::Trace`), and code generation writes the rows from the
unit, its sites and `Lines` (now with columns, and the origins code was inlined from). How much it
describes is a build option read at compile time (`lang.trace.Detail`: `off`, `sites`, `calls`;
`Options.trace`, `--trace`; `calls` in debug builds, `sites` in release ones), rather than a host
decoding a record the program writes, which would tie `vun run` to a text format. `std.trace.report`
names why the program ends (`Why`: a trap, or a failed check with its `lang.check.Violation`, named
by reflection, `std.meta.variant_name`), the site's place and each function its code is inlined into
(sites placed by inlining get origins `Via::Inline { into }`), then the chain of frame records (C
gains `-fno-omit-frame-pointer`; arm64's `xpaclri` strips signed return addresses), past the
handler's frames, up to the first function foreign code calls (C convention or naked). At `calls`, a
callee is inlined only when none of its calls returns into it, so every return address lies in the
code of the function named for it, on every backend. Fixed on the way: a linked datum is stored at
its symbol (it was encoded as its address); the C backend clobbers only the registers a block may
overwrite (`Blocks::overwritten`); compile-time `a == .b` gives `.b` the type of `a`
