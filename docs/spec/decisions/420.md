# 420. What a form needs when compiling reads nothing the body computes when it runs

Status: accepted
Where: 03, 08, 13

What a form needs when compiling reads nothing the body computes when it runs: the length of an
array, in its type or in a repeated value, that reads a local bound without `$` is
`comptime.runtime`, as a `$` form is, where it was left untyped without a report and reached
lowering as a compiler bug. A Windows program is started with every argument its command line can
hold, the arguments and their bytes sized from the system's 32767 units
(`std.os.windows.command_line_max`) so starting never traps for their number or length; a surrogate
without its partner in the command line is U+FFFD, as invalid UTF-8 is read; the real clock set
before 1970 reads as the epoch. The readers of ELF and PE files, which `vun debug disasm` runs on
any file, check every address and size taken from the file, read a name within `vun_bytes::NAME_MAX`
(4096) bytes, copy from the file no more than its length (`vun_bytes::Copies`: a file's sections and
a PE file's import slots hold each byte once), and a PE file has at most the 96 sections the loader
takes; `fuzz/` has the targets `elf`, `pe` and `disasm`. `Convention::name` is the one spelling of a
calling convention, and the C backend writes one only for those a function can name. `coverage`
counts a closure written outside any function that no program reaches as run at compile time, not
unreached
