Status: accepted

Editors read Vun through a tree-sitter grammar generated from `nodes.vun` and `grammar.vun`
(`vun-tree-sitter` models grammars and queries): a rule per production, fields holding what the
tables `admits` and `holds` say or any operand (`parts` are never operands), precedences from
`precedence` (with `infix`'s levels), lists precise (an entry ends with `;` unless `unterminated`,
through `transparent` kinds by `.ending`), a field restricted by its first token (`.starting`) or by
kinds (`.of`), `line_ends` through an external scanner, `preferred` giving the kind the parser keeps
where several fit; the sets tree-sitter must keep apart are found by `cargo xtask tree-sitter`
(`conflicts.json`), which also generates the parser and compares its tree with the compiler's on
every source (192 of 198 agree). Queries are built once with typed captures and written per editor
dialect; `cargo gen` writes the Helix, Neovim, Zed and VS Code packages (the VS Code grammar is the
Sublime syntax as `TextMate`); what an editor runs as code is written by hand and reads the
generated data. The parser (`parser.c`, 8 MiB) is published in a repository of its own,
`tree-sitter-vun`
