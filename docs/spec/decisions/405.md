# 405. A function written as an argument, a closure or a literal without a capture

Status: accepted
Where: 1

A function written as an argument, a closure or a literal without a capture list, takes the types of
the parameters it leaves out from what the call expects of it, and its result when it writes none:
from a function type the parameter is annotated with, or from `lang.ops.Call(P, R)` constraining the
`$` parameter it binds (`Typer::argument_context`), else the type of its body (typed once in the
body that holds it for its type, and again on its own, which reports). A call of a value known by a
`Call` constraint in a generic body is a call of the requirement, a `(T)` one-parameter list taking
the argument as it is. It is typed after the other arguments, with the `$` parameters inferred so
far bound, and the type the call is expected to have is matched against the callee's result type as
one more source of them (`Unifier::infer`), so `fold(0, f)` expected to give `u32` is `u32`; the
exact type of an integer literal alone is not used for a parameter. Where the function is checked or
lowered on its own, its signature is the type typing the body that holds it recorded for it
(`Env::context`)
