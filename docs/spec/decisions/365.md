# 365. Every target is at a path of one rule, `targets.<os>.<arch>.<abi>`

Status: accepted
Where: 12, 13
Note: the user chose the rule

Every target is at a path of one rule, `targets.<os>.<arch>.<abi>`: a system is a namespace, an
architecture a namespace in it (on bare metal, which has no baseline machine, an instruction set
profile, `thumbv7em`), each target in it an ABI: `linux.x86_64.kernel`, `linux.x86_64.gnu`,
`linux.arm64.kernel`, `linux.arm.kernel`, `linux.riscv64.gnu`, `macos.arm64.darwin`,
`wasi.wasm32.p1`, `bare.thumbv7em.eabihf`, `bare.thumbv7m.eabi`, `bare.riscv32imc.ilp32`. Bare
targets are generic for their profile (`cpu = generic`, `-march`), and a board names the target of
its processor (`stm32f4.target`, `esp32c3.target`). `targets.hosts` is a list of targets, the first
whose `arch` and `os` are the running machine's chosen (`vun_target::Machine::RUNNING`, Rust's names
but `arm64` for `aarch64`), so `lang.target.Host` and a second vocabulary of machines are gone.
`vun-items` has a handle per target, and Rust names a target by one
(`Choice::of(targets::linux_x86_64::kernel)`), never by its path as text
