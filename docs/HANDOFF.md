# Handoff

is durable; conventions and how-tos live in [`dev/`](dev/workflow.md), rules in
[`spec/`](spec/00-principles.md), history in `jj log` and [`decisions.md`](spec/decisions.md).

## State

Everything is committed in the main chain; no `jj` workspace holds work. 667 tests pass; clippy,
`cargo gen --check`, `lines` and `layers` are clean; the corpus has 304 passing programs and 4
planned, and LIR lowers every function the corpus reaches.

Built: the front end, packages and the store, the persisted parallel query engine, sema, MIR and
its checks, LIR with legalization, the C and wasm backends, the native backend for x86-64, arm64
and Thumb-2, ELF and Mach-O objects, the `gnu`, `mold` and `wild` linkers, the toolchain file,
static Linux runtimes calling the kernel (threads, storage per thread, files, clocks),
backtraces. Programs run through either backend on linux.x86_64, linux.arm64, linux.arm (through
`qemu`) and wasi.wasm32.

columns; the overlays are not yet tried in OBS itself.

## Known gaps in landed work

- A `$`-generic C import (a pack inferred per call) is typed nowhere yet: such calls stay
  silently untyped (decisions 285, 286).
- ABI: legalize splits a soft `f64` by `Rules::fits`; `Rules` should be declared in `lang` and
  generated; no target check yet that the convention's word matches `pointer_bits`.
- Backtraces: no call line per frame (native marks each call's origin; C cannot say where a
  call returns); no macOS (compact unwind, PAC). WASI reports the site only.
- Mach-O arm64 thread-locals are checked by linking with `ld64.lld`, never run on a Mac.
- A new project still writes a whole new shared memo file (~450 ms dev, after the build): memos
  whose keys name the project's functions but read shared inputs alone count as shared.
- Truly cold (empty store), threads wait ~1.1 s on the same `std` claims, once per toolchain.

## Next steps, most useful first

0. Editor integration (the owner's current focus; editors: Zed, Helix, VS Code, Neovim). The
   parser reads the productions (340) and every source agrees with tree-sitter. In order:
   (a) inline assembly as ordinary Vun, the owner's choice: a block is a quote of calls,
   `asm(#{ mov(rdi, rsp); \and(rsp, -16); call(_boot); })`, its names brought in by a spread
   (`..lang.arch.x86_64;`): `lang.arch.<arch>` declares each register (at each width) and each
   mnemonic (the members of a family too) as declarations, memory operands as `mem(...)`,
   write-back as `pre`/`post`, outputs as `out(p)`/`inout(p)`, a register binding explicit, a
   label a value (`top := label();`); sema reads the quote's typed HIR against the table as it
   reads the `Asm` HIR today. The `asm`, `line`, `suffix`, `bound` and `memory` kinds,
   `operand_contexts` and `line_ends` then leave the grammar, and with them the engine's line and
   context handling. 55 blocks in `lib/` and the corpus change; spec 07 section 6, spec 01, the
   decision replacing 258;
   (b) the owner publishes `tree-sitter-vun` by hand (`docs/dev/commands.md`, "Publishing the
   tree-sitter grammar"); the packages pin the revision in `editors/tree-sitter/release.json`;
   (c) try the packages in each editor (nothing was run in an editor yet; the Zed extension
   passes `cargo check`), and the LSP features (324) in them.
   Gap: a doc comment on a record's field (`.{ /// d\n .x = 1 }`) reads as a doc of an assignment
   in tree-sitter, which cannot tell a `doc`'s list apart (`editors.vun` uses `//` inside records
   for now); `FromLiteral` could replace the hand walks of `Literal` in manifests, the lock file
   and the toolchain file.
