# Repository

```
lib/lang/lang/syntax/{grammar,desugar}.vun   tokens, nodes, parse tables; appendix B as tables
lib/lang/lang/errors.vun + errors/           every diagnostic id and its explanation page
lib/lang, lib/std, lib/targets               `lang` primitives, `std`, one `lang.target.Spec` per target
corpus/{accept,reject,planned,support}       programs; `//~ id` annotations; waiting for APIs; stand-ins
compiler/<group>/<crate>                     see crates.md; layering in spec 13 section 9
fuzz/                                        cargo-fuzz targets (a workspace member)
whitepaper/                                  Typst paper; it quotes real numbers and `vun` output
editors/                                     editor grammars, generated from `grammar.vun` by `cargo gen`
docs/                                        spec, decisions, these notes, research, references
assets/{logo,cards}, assets/palette.toml     logo SVGs and animations; Typst cards (code, social, icon) and their PNGs
README.md, CONTRIBUTING.md, LICENSE-*        for people: pitch, how to try, how to contribute; MIT OR Apache-2.0
```

`site/` is the owner's and untracked.

## Generated directories

Never edited by hand: edit the `.vun` source, then run `cargo gen`, which also removes files no
longer generated. Generated files are held to the 300-line limit too.

| Directory | Source |
|-----------|--------|
| `compiler/lang/grammar/src/generated/` | `lib/lang/lang/syntax/grammar.vun` |
| `compiler/front/desugar/src/generated/` | `lib/lang/lang/syntax/desugar.vun` |
| `compiler/base/diag/src/errors/` | `lib/lang/lang/errors.vun` |
| `compiler/lang/primitives/src/generated/` | the `= _` declarations of `lib/lang` |
| `compiler/lang/items/src/{lang,std,targets}/` | a handle per public declaration of `lib` |

Rust names `lang` and `std` items only through `vun_items`.

## Assets

```
assets/palette.toml         brand schemes (light, dark, rose, mono) the cards read
assets/logo/                hand-drawn SVGs: wordmark/, mark/, icon/, construction.svg, motion/
assets/logo/logo.typ        the logo's geometry for Typst, in the coordinates of wordmark/*.svg
assets/cards/<card>/        card.typ and its PNGs, one per variant: code/, social/, icon/, moods/, lockup/;
                            a card's mascot/ holds its versions with the mascot
assets/mascot/              the mascot, generated by `pnpm mascot` in assets/motion: stills, adaptive
                            (<mood>.svg) and per scheme (<scheme>/<mood>.svg), CSS animations (motion/)
assets/motion/              Motion Canvas projects (videos): sting, sting-mascot, mascot
```

`*/adaptive.svg` follow `prefers-color-scheme`; `mono.svg` strokes in `currentColor`; `motion/`
animates with CSS and stills under `prefers-reduced-motion`. The logo's geometry is written twice,
in the SVGs and in `logo.typ`: a change to one is made to the other.

`cargo xtask typeset` compiles the table `typeset::ALL` of `xtask` (the whitepaper and the
cards), in parallel. A card with variants declares them itself as `#metadata(..) <variants>`: an
array of `(path: (..), inputs: (..))`, each compiled with its `sys.inputs` to
`<dir>/<path>.png`. Adding a scheme to `palette.toml` or a size to a card adds its outputs; a
variant removed leaves its old PNG to delete by hand. The cards draw at 72 pixels per inch, so a
point is a pixel.

The code card renders `corpus/accept/programs/tour.vun` (so the corpus keeps it compiling) with
`editors/sublime/vun.sublime-syntax` (generated from the grammar), in the colors of
`assets/cards/code/colors.toml` and JetBrains Mono. Regenerate after changing any of them.

`assets/motion` holds Motion Canvas projects, one per video (`src/<project>.ts`, its scenes in
`src/scenes/`): `pnpm install`, then `pnpm start` opens the editor, where a project renders (its
`scheme` variable names a scheme of `palette.toml`). The scenes draw from the repository's
sources rather than copies: `src/brand/` reads `palette.toml` and the logo's SVGs
(`construction.svg` by the ids of its groups: `grid`, `guides`, `circles`, `strokes`, `joints`,
`centers`). Not to be confused with `assets/logo/motion/`, the CSS animations.

| project | what it shows |
|---|---|
| `sting` | the logo built on its construction grid: traced, swelled to weight, the word landing, the v wagging on its tip |
| `sting-mascot` | the sting, then the word making room and the mascot dropping in beside it (the variable `mascot`) |
| `mascot` | the mascot dropping in, looking around, going through each mood, then its moods lined up |

The mascot is declared once, in `src/mascot/`: `shape.ts` its geometry (a box with arc corners,
outlined so its corners round; eyes and mouth as curves described by numbers,
so faces blend), `moods.ts` a face and a pose per mood, `Mascot.tsx` the component the scenes move
(`feel`, `blink`, `glance`, `hop`, `shake`, `breathe`). `pnpm mascot` writes `assets/mascot/`
from them (and `scripts/motions.mts`, its CSS animations), clearing it first; never edit it by
hand. The cards draw the mascot from those stills through `assets/cards/mascot.typ`, which reads
the moods from the `mascot.toml` written beside them: after changing the mascot, run
`pnpm mascot`, then `cargo xtask typeset`. A card's versions with the mascot are variants under
its `mascot/` directory, beside the ones without. `tools/body.html`, opened by `pnpm body` (it needs the
dev server, which compiles the modules it imports), designs the body and face placement over the grid with every mood
previewed, and prints the `DESIGN` constant of `shape.ts` to paste over it.
